DISCOVERING THE DATABASE WORLD · 01

01. The Story Behind MySQL — How It All Started

Before starting to write SQL queries, create tables or insert records, I wanted to understand something more fundamental: Where did MySQL come from? Who developed it, why was it created, and what problem was it designed to solve?

Until now, my learning journey had introduced me to HTML for creating webpage structures, CSS for designing them, JavaScript for adding interactions, and Bootstrap for building responsive layouts. But when I started exploring backend development, another question appeared: where does all the information submitted through a website actually go?

"A website does not only need to display information. It also needs a reliable way to remember, organise and retrieve that information."

1.1 Before MySQL — Understanding the Need for Databases

Imagine a college website that allows students to register for admission. Every student enters details such as their name, email address, phone number, course and application information.

Now imagine that hundreds or thousands of students submit their details. Where should the website keep all these records? How would the administrator find one particular student's information? How could the website update an email address without disturbing other students' records?

These questions explain why organised data storage became an important part of computer systems. As applications grew, developers needed systems that could store, manage, search and retrieve information efficiently.

A real-world situation

  • A college needs to store student admission records.
  • A bank needs to manage customer accounts and transactions.
  • An online shopping website needs product, customer and order information.
  • A hospital needs to organise patient and appointment records.

Each situation requires an organised method of managing information instead of depending on scattered, unstructured records.

1.2 The Birth of MySQL — When Did It Appear?

MySQL began its development journey in the early 1990s and was first released in 1995. It was created by a Swedish company called MySQL AB, with its original development associated with Michael "Monty" Widenius, David Axmark and Allan Larsson.

Michael Widenius, commonly known as Monty, was one of the central creators of MySQL. The development team wanted to build a database system that could manage information efficiently and work well with web applications.

MySQL became especially popular because it offered a practical way to store and retrieve structured information for websites and other applications.

1.3 Why Was MySQL Created?

MySQL was developed to provide a database management solution for applications that needed reliable and efficient data handling.

Developers needed more than a simple place to keep information. They needed a system that could perform operations such as:

  • Storing large collections of structured information.
  • Retrieving specific records whenever required.
  • Updating existing information.
  • Removing records that were no longer required.
  • Organising information into related tables.
  • Allowing applications to communicate with stored data.
  • Supporting multiple users and database operations.

In simple words, MySQL helps an application maintain its information instead of losing everything whenever a webpage is refreshed or closed.

1.4 Who Created MySQL?

The people behind MySQL

  • Michael "Monty" Widenius: One of the original developers and a key figure behind the creation of MySQL.
  • David Axmark: Co-founder and contributor to the early development of MySQL.
  • Allan Larsson: One of the people associated with the early MySQL company and its development.

1.5 In Which Programming Languages Was MySQL Developed?

Another interesting part of its history is the technology used to develop MySQL itself. MySQL's server implementation is primarily written in C and C++.

These languages are known for their performance and low-level system capabilities, making them suitable for developing database software.

1.6 How Did the Name MySQL Come About?

Have you ever wondered why this database is called MySQL?

The commonly shared explanation connects the word "My" with My, the name of Michael Widenius's daughter, and "SQL", which stands for Structured Query Language. However, accounts of the exact naming origin are not entirely consistent.

SQL is the language used to communicate with relational database systems. The name MySQL therefore became closely associated with a database system that supports SQL.

1.7 How Has MySQL Grown Over Time?

MySQL started as a database project and gradually developed into one of the widely used relational database management systems.

A simplified historical timeline

  • Early 1990s: The development work behind MySQL began.
  • 1995: MySQL was first released.
  • 2000s: Its popularity grew alongside dynamic websites and web application development.
  • 2008: Sun Microsystems acquired MySQL AB.
  • 2010: Oracle completed its acquisition of Sun Microsystems.
  • Today: MySQL continues to be developed and used for websites, business applications and many other data-driven systems.

02. Understanding MySQL and SQL — Are They the Same?

After exploring the history of MySQL, my next question was: What exactly is MySQL, and why do developers use it? I had heard the terms SQL and MySQL many times, but initially, I was not completely clear about their individual roles.

While learning backend development, I realised that a website does not only need a beautiful interface. It may also need to remember users, store their details, save messages, manage products, and retrieve information whenever required. This is where databases become important.

2.1 What Is MySQL?

MySQL is a Relational Database Management System (RDBMS). It is software that helps us create databases, organise information into tables, store records, retrieve data, and manage relationships between different tables.

In simple words, I can think of MySQL as a system that manages the information used by a website or application.

For example, imagine I am developing a portfolio website with a contact form. Whenever a visitor submits their name, email address, and message, I may want to save that information so I can read it later. MySQL can manage that stored information.

A Real-World Example: Portfolio Contact Form

Suppose a visitor submits the following details:

MySQL can store these details in a database table. Later, the website can retrieve the saved message and display it in an approved feedback section.

2.2 What Is SQL?

After understanding MySQL, I came across another important term: SQL, which stands for Structured Query Language.

SQL is a language used to communicate with relational databases. We write SQL statements, commonly called queries, to tell a database what operation we want to perform.

For example, if I want to retrieve all records from a table, I can write a SQL query like this:

SQL Query 
SELECT * FROM contact_messages;

Here, I am asking the database to display all columns and records stored inside the contact_messages table. We will understand each part of this query in detail in the upcoming chapters.

2.3 MySQL vs SQL — Understanding the Difference

At first, the names MySQL and SQL seemed almost identical to me. However, I learned that they are not the same thing. Their relationship is similar to the relationship between a language and the software that understands and uses it.

My Understanding

  • SQL: The language used to write commands and communicate with relational databases.
  • MySQL: Database management software that understands and executes SQL statements.

Examples include SELECT, INSERT, UPDATE and DELETE. Examples include MySQL Server and MySQL Workbench.

2.4 How Do SQL and MySQL Work Together?

Understanding their definitions was helpful, but I also wanted to understand how they work together when an actual application needs to store or retrieve information.

Consider a simple example: I want to see all messages submitted through my portfolio contact form.

  1. First, I write an SQL query requesting the required information.
  2. The query is sent to the MySQL database server.
  3. MySQL processes the SQL statement.
  4. MySQL accesses the relevant table and retrieves the requested data.
  5. The result is returned to the application.
Example: Requesting Data from MySQL 
SELECT * FROM contact_messages;

My Understanding of Their Relationship

MySQL = Software that manages the database

2.5 What Is a MySQL Server?

While exploring MySQL, I also learned about the term MySQL Server.

MySQL Server is the main database service that receives database requests, processes SQL statements, manages access to data, and returns results to connected applications.

It can run on the same computer as the application or on another computer connected through a network.

For example, when I run a PHP project using XAMPP on my computer, the MySQL database service can run locally and handle database requests from my PHP application.

MySQL Server and MySQL Workbench Are Different

  • MySQL Server: The database service responsible for storing, processing, and managing data.
  • MySQL Workbench: A graphical tool that helps developers work with MySQL databases, write SQL queries, and manage database objects.

This distinction helped me understand that a graphical interface is not the database server itself. It is a tool that can connect to and work with the server.

03. The LAMP Stack — Understanding How Web Technologies Work Together

After understanding the relationship between SQL and MySQL, I wanted to explore how database technology fits into the complete web development environment.

Until this point, I had learned about different technologies separately. HTML structures a webpage, CSS styles it, JavaScript adds interaction, PHP handles server-side logic, and MySQL manages stored information.

But how do these technologies work together when someone visits a dynamic website?

While exploring backend development, I came across a term called LAMP Stack. It helped me understand how multiple technologies can work together to run a web application.

3.1 What Is a Stack in Web Development?

Before understanding LAMP, I first wanted to understand the word Stack.

In web development, a technology stack means a collection of technologies, tools, and software that work together to build and run an application.

Instead of depending on only one technology, a web application usually uses different technologies for different responsibilities.

Understanding Through a Simple Example

Imagine I am developing a website where visitors can submit contact forms.

  • HTML creates the form structure.
  • CSS controls its appearance.
  • JavaScript can handle browser-side interactions.
  • PHP processes the submitted information on the server.
  • MySQL stores the submitted records.

These technologies have different jobs, but together they help create a working application.

3.2 What Does LAMP Stand For?

LAMP is a popular open-source web development stack. Its name comes from the first letters of four technologies:

Letter Technology Main Responsibility
L Linux Operating system
A Apache Web server
M MySQL Database management system
P PHP Server-side programming language

These four components have different responsibilities. Together, they provide an environment in which developers can build and run dynamic web applications.

3.3 Understanding Each Component of LAMP

A. Linux — The Operating System

Linux is an open-source operating system. It manages the computer's hardware and software resources and provides the environment in which server applications can run.

In a LAMP environment, Linux acts as the foundation on which the other components operate.

My Understanding

I can think of Linux as the working environment that supports the web server, PHP, and database services.

B. Apache — The Web Server

Apache HTTP Server is web server software. It receives HTTP requests from browsers and helps deliver the requested web resources.

For example, when a visitor opens a website, the browser sends a request. Apache can receive that request and serve the appropriate content.

When a request needs PHP processing, Apache can work with PHP through a configured PHP integration.

My Understanding

Apache acts as the web server that handles incoming browser requests and helps serve website content.

C. MySQL — The Database Management System

MySQL is responsible for managing relational databases. It stores information in tables and allows applications to insert, retrieve, update, and delete records.

For example, a website may use MySQL to store visitor messages, registered users, product details, or orders.

My Understanding

MySQL works as the data management component of this stack. It helps an application remember and manage information.

D. PHP — The Server-Side Programming Language

PHP is a server-side scripting language used to develop dynamic web applications.

It can receive form data, validate user input, perform application logic, communicate with MySQL, and generate responses for the browser.

For example, when someone submits a contact form, PHP can receive the submitted details and send an appropriate database query to MySQL.

My Understanding

PHP works as the backend logic that connects application requests with database operations.

04. What Is a Database? — Understanding How Information Is Stored

After understanding the LAMP Stack, my next step was to explore the most important concept behind MySQL: the database itself.

Before learning SQL commands, I wanted to understand what kind of information we actually store, why we store it, and how a database keeps that information organised.

I started connecting this concept with everyday examples. Whenever we create an account on a website, place an online order, send a message, or book a ticket, some information needs to be stored and managed.

This made me realise that databases are not limited to programming exercises. They are an important part of many applications and digital services that we use daily.

4.1 What Is a Database?

A database is an organised collection of related data that can be stored, accessed, managed, updated, and retrieved whenever required.

In simple words, I can think of a database as a digital place where an application keeps its important information in an organised manner.

For example, an online shopping website may need to store:

  • Customer names and contact details.
  • Product names, prices, and descriptions.
  • Customer orders and their order dates.
  • Payment and delivery information.
  • Product availability and stock quantities.

Instead of keeping all this information in separate, unorganised notes, a database provides a structured way to manage it.

My Simple Understanding

Imagine a school maintaining information about hundreds of students. It needs to remember their names, roll numbers, classes, contact details, and examination results.

A database can store this information in an organised structure so that the school can search, update, and retrieve student records when needed.

4.2 Why Do We Need a Database?

Initially, I thought that information could simply be written in a text file or spreadsheet. But as information grows, managing it manually becomes difficult.

Think about a website that receives hundreds or thousands of contact messages. If every message is saved in a separate text file, finding a particular visitor's message or updating a record can become inconvenient.

A database helps solve many of these problems.

Some Important Reasons for Using Databases

  • Organised storage: Information can be arranged into meaningful structures such as tables and records.
  • Easy retrieval: We can search for specific information instead of manually checking every stored record.
  • Updating information: Existing records can be modified when details change.
  • Data management: We can insert new records, update existing data, and remove information when appropriate.
  • Reduced unnecessary duplication: A well-designed database can organise information into related tables and avoid repeatedly storing the same details.
  • Controlled access: Database systems provide ways to manage who can access or modify information.
  • Application integration: Websites and software applications can communicate with databases to work with stored information.

4.5 Understanding Tables, Rows, Columns, and Fields

While exploring relational databases, I came across four important terms: table, row, column, and field. These terms describe how information is arranged.

A. Table

A table is a database object that stores related information in rows and columns. Every table has a name that describes the information it contains.

For example, a table named students stores student-related information.

B. Row or Record

A row, also called a record, represents one complete entry in a table. Each row contains related values describing one particular item or person.

For example, one row in the students table can represent one student's details.

C. Column or Field

A column represents a particular category of information stored in a table. It has a name and a data type.

For example, the students table may have columns such as student_id, student_name, age, and class_name.

The terms field and column are often used interchangeably in introductory database learning. More precisely, a field can also refer to an individual value at the intersection of a row and column.

D. Data or Field Value

A field value is the actual information stored at the intersection of a particular row and column.

While learning about databases, I also wanted to understand the difference between data and information. These terms are related, but they do not always mean exactly the same thing.

  • Information: Data that has been organised or interpreted so that it becomes meaningful and useful.

4.7 Database vs Spreadsheet — Are They the Same?

Because tables look similar to spreadsheets, I initially wondered whether a database was simply another type of Excel sheet.

Both can organise information in rows and columns, but they are designed for different purposes.

Spreadsheet Database
Commonly used for calculations, lists, and analysis. Designed to manage structured collections of data.
Often managed through spreadsheet software. Managed through a Database Management System (DBMS).
Suitable for many individual and small-team tasks. Can support applications with large and connected datasets.

This does not mean that spreadsheets are useless for storing information. They are useful tools. However, when an application needs structured data management, relationships, controlled access, and repeated operations, a database system is often more suitable.

4.8 What Is a DBMS?

While reading about databases, I came across another important term: Database Management System (DBMS).

A DBMS is software that allows users and applications to create, store, organise, retrieve, update, and manage data in databases.

A database is the organised collection of data, whereas a DBMS is the software used to manage it.

Some Examples of DBMS Software

  • MySQL
  • PostgreSQL
  • Oracle Database
  • Microsoft SQL Server
  • SQLite

These systems provide different features and capabilities for managing data.

4.9 What Is a Relational Database?

Since MySQL is a Relational Database Management System, I wanted to understand what the word Relational actually means.

A relational database stores information in tables and allows those tables to be connected through common fields and relationships.

For example, instead of storing all customer and order details repeatedly in one large table, an application can maintain separate tables for customers and orders.

4.10 What Happens When a Database Is Poorly Organised?

While understanding database structure, I also learned why proper organisation matters.

Imagine storing customer details and every order in one large table, repeating the customer's name, phone number, and address for every order.

This can create unnecessary duplication. If a customer's phone number changes, we may need to update several records. If one record is missed, inconsistent information can appear.

A properly designed database separates information into meaningful tables and establishes relationships where required. This helps reduce unnecessary repetition and makes data easier to manage.

This process of organising relational database structures to reduce redundancy is connected with a concept called normalization. I will explore it further as my database learning progresses.

05. Database Structure and Formatting — How Data Gets Organised

After understanding what a database is, I wanted to explore how information is arranged inside it. I learned that a database is not just a collection of random values. It needs a proper structure so that information can be stored and accessed meaningfully.

While working with MySQL concepts, I started noticing that every table has a name, every column has a purpose, and every column is designed to store a particular kind of value.

This made me realise that database structure and data formatting are important parts of database design.

5.1 What Is Database Structure?

Database structure refers to the way data is organised inside a database. In a relational database, this structure commonly includes databases, tables, columns, rows, keys, and relationships.

For example, if I create a database for a portfolio website, I may need separate tables for contact messages, visitors, and feedback.

A database schema describes the logical structure of a database. It defines how database objects such as tables, columns, data types, keys, and relationships are organised.

In simple words, I can think of a schema as a blueprint of a database. It explains how the database is designed before or while information is stored in it.

7.1 What Is an SQL Database?

One important difference I noticed was how database schemas are designed.

In SQL databases, relationships are commonly managed through primary keys and foreign keys.

08. Understanding RDBMS — How Relational Databases Work

While learning about SQL and NoSQL databases, I came across another important term: RDBMS. I understood that MySQL is not just a tool for writing SQL queries; it is also a Relational Database Management System.

This made me curious about what the word "relational" actually means. I wanted to understand how tables store information, how one table can be connected to another, and how these relationships help an application manage data.

8.1 What Is RDBMS?

RDBMS stands for Relational Database Management System. It is a type of database management system that stores and manages data using tables.

Each table contains rows and columns. Rows represent individual records, while columns represent the attributes or properties of those records.

The word relational refers to the ability to establish relationships between tables. These relationships allow us to connect related information without unnecessarily repeating the same data in multiple places.

Understanding Through a Simple Example

Imagine that I am building a college management application. I need to store information about students and the courses they have selected.

Instead of storing every student's complete course information repeatedly, I can create separate tables and connect them through common identifiers.

8.2 Understanding Tables, Rows, and Columns

Before creating relationships, I first need to understand the basic structure of an RDBMS table.

  • Table: A structured collection of related data.
  • Row: A single record inside a table.
  • Column: A particular property or attribute of the records.
  • Field: A particular value at the intersection of a row and a column.
  • Schema: The defined structure of a database, including its tables, columns, data types, and relationships.
Example — Students Table 
+------------+--------------+-------+
| student_id | student_name | age   |
+------------+--------------+-------+
| 1          | Pooja        | 22    |
| 2          | Aman         | 21    |
| 3          | Simran       | 23    |
+------------+--------------+-------+

In this example, Students is the table name. The columns are student_id, student_name, and age. Each row represents one student record.

8.3 Why Do We Need Relationships Between Tables?

Suppose I have a table containing student details and another table containing course details. If I want to know which student has selected which course, I need a way to connect the information.

One approach would be to repeat course information inside every student record. But this can create unnecessary duplication. If a course name changes, I might need to update it in many different records.

A relational database helps organize this information into separate tables and connect them using keys.

8.4 Understanding Primary Keys

A Primary Key is a column, or combination of columns, used to uniquely identify each record in a table.

A primary key must contain unique values and cannot contain NULL. Each table can have only one primary key constraint, although that key can contain multiple columns.

SQL — Creating a Primary Key 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(100),
    age INT
);

Here, student_id uniquely identifies each student. Two students cannot have the same student_id in this table.

8.5 Understanding Foreign Keys

A Foreign Key is a column, or combination of columns, that creates a relationship with a candidate key in another table, commonly its primary key.

It helps maintain referential integrity. This means the database can prevent a record from referring to a parent record that does not exist, subject to the foreign key rules and actions.

SQL — Creating Related Tables 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(100)
);

CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(100)
);

CREATE TABLE student_courses (
    student_id INT,
    course_id INT,

    PRIMARY KEY (student_id, course_id),

    FOREIGN KEY (student_id)
    REFERENCES students(student_id),

    FOREIGN KEY (course_id)
    REFERENCES courses(course_id)
);

In this example, the student_courses table connects students with courses. Its two foreign keys refer to the students and courses tables.

I also noticed that the student_courses table uses a composite primary key. It combines student_id and course_id so that the same student-course combination cannot be inserted twice.

8.6 Understanding Different Types of Relationships

While studying relational databases, I learned that tables can be connected in different ways. These are commonly known as database relationships.

One-to-One Relationship (1:1)

In a one-to-one relationship, one record in the first table is associated with at most one record in the second table, and vice versa.

Example: A person and a separate passport-details record. The exact relationship depends on the application's rules.

In a one-to-many relationship, one record in the first table can be connected to multiple records in the second table.

Example: One customer can place multiple orders, but each order belongs to one customer.

In a many-to-many relationship, multiple records in one table can be connected to multiple records in another table.

Example: A student can select multiple courses, and each course can have multiple students.

8.7 What Is Referential Integrity?

Referential integrity is a rule that keeps relationships between tables valid.

For example, if an order refers to customer_id 10, the database should ensure that the referenced customer exists when a foreign key constraint is enforced.

This helps prevent invalid references and keeps connected records consistent.

Foreign keys can also define what happens when a referenced record is updated or deleted. Common actions include:

  • CASCADE: Applies the update or deletion to related child records.
  • SET NULL: Sets the foreign key value in related child records to NULL, when the column allows it.
  • RESTRICT: Prevents an operation that would violate the relationship.
  • NO ACTION: Does not automatically change the child record; enforcement behavior depends on the database system.
SQL — Foreign Key with CASCADE 
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,

    FOREIGN KEY (customer_id)
    REFERENCES customers(customer_id)
    ON DELETE CASCADE
    ON UPDATE CASCADE
);

In this example, deleting a referenced customer also deletes the related order records. This is why choosing foreign key actions carefully is important.

8.8 What Is Normalization?

As I explored relational database design, I came across Normalization. It is a process of organizing data into tables to reduce unnecessary duplication and avoid certain data anomalies.

Imagine storing customer information repeatedly in every order record. If the customer's address changes, we may need to update several rows.

Normalization helps us separate related information into appropriate tables and connect them through keys.

Common Normal Forms

  • First Normal Form (1NF): Each column should contain atomic values, and repeating groups should be avoided.
  • Second Normal Form (2NF): The table should satisfy 1NF, and every non-key attribute should depend on the whole candidate key, not just part of a composite key.
  • Third Normal Form (3NF): The table should satisfy 2NF and avoid transitive dependencies of non-key attributes on candidate keys.

I understood that normalization is not simply about creating more tables. It is about designing tables logically so that data remains consistent and easier to maintain.

  • SQLite: A lightweight, serverless relational database engine often used in mobile, desktop, and embedded applications.

09. SQL Commands and Their Categories — Understanding How We Communicate with a Database

After understanding databases, tables, relationships, and RDBMS, I wanted to learn how we actually communicate with a database. How do we create a database? How do we insert information? How can we retrieve, update, or delete records?

I discovered that SQL provides different commands for performing these operations. Instead of treating every SQL command as the same, we classify them into different groups according to their purpose.

The five commonly taught categories of SQL commands are:

  • DDL: Data Definition Language
  • DQL: Data Query Language
  • DML: Data Manipulation Language
  • DCL: Data Control Language
  • TCL: Transaction Control Language

9.1 Understanding the Five SQL Command Categories

Each category has a different responsibility. Some commands define the structure of a database, some work with the records, some retrieve information, while others control permissions and transactions.

Category Full Form Main Purpose Common Commands
DDL Data Definition Language Defines database structures. CREATE, ALTER, DROP, TRUNCATE
DQL Data Query Language Retrieves information. SELECT
DML Data Manipulation Language Changes table records. INSERT, UPDATE, DELETE
DCL Data Control Language Controls database permissions. GRANT, REVOKE
TCL Transaction Control Language Manages transactions. COMMIT, ROLLBACK, SAVEPOINT

9.2 DDL — Data Definition Language

DDL stands for Data Definition Language. It is used to define and modify the structure of database objects such as databases, tables, and columns.

When I create a new database or design a table, I am working with DDL commands. These commands focus on the structure rather than the individual records stored inside a table.

1. CREATE Command

The CREATE command is used to create database objects. For example, we can create a database or a new table.

SQL — CREATE DATABASE 
CREATE DATABASE portfolio_contact;

To create a table inside a database:

SQL — CREATE TABLE 
CREATE TABLE contact_messages (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(150),
    message TEXT
);

2. ALTER Command

ALTER is used when we want to change the structure of an existing table. We can add, modify, rename, or remove columns.

Adding a new column:

SQL — ADD COLUMN 
ALTER TABLE contact_messages
ADD created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP;

Changing a column's data type in MySQL:

SQL — MODIFY COLUMN 
ALTER TABLE contact_messages
MODIFY name VARCHAR(150) NOT NULL;

Renaming a column in MySQL:

SQL — RENAME COLUMN 
ALTER TABLE contact_messages
RENAME COLUMN name TO visitor_name;

Removing a column:

SQL — DROP COLUMN 
ALTER TABLE contact_messages
DROP COLUMN visitor_name;

3. DROP Command

DROP is used to permanently remove a database object, such as a table or database.

SQL — DROP TABLE 
DROP TABLE contact_messages;

Removing an entire database:

SQL — DROP DATABASE 
DROP DATABASE portfolio_contact;

I learned to be careful with DROP because it removes the database object itself, not just its records.

4. TRUNCATE Command

TRUNCATE removes all rows from a table while keeping its table structure. It is useful when we want to empty a table without dropping and recreating it.

SQL — TRUNCATE TABLE 
TRUNCATE TABLE contact_messages;

In MySQL, TRUNCATE is treated as a DDL operation and generally causes an implicit commit. It should not be confused with DELETE, which is a DML command.

9.3 DQL — Data Query Language

DQL stands for Data Query Language. It is used to retrieve information from database tables.

The most important command in this category is SELECT. Whenever I want to view records stored in a table, I use SELECT.

SELECT — Retrieving All Records

SQL — SELECT * 
SELECT * FROM contact_messages;

The asterisk (*) represents all columns. This query retrieves all columns from the contact_messages table.

SELECT — Retrieving Specific Columns

SQL — Selecting Particular Columns 
SELECT name, email
FROM contact_messages;

This query retrieves only the name and email columns. It does not display every column in the table.

SELECT with WHERE

SQL — Filtering Records 
SELECT *
FROM contact_messages
WHERE name = 'Pooja';

WHERE allows us to retrieve only those records that satisfy a particular condition.

9.4 DML — Data Manipulation Language

DML stands for Data Manipulation Language. It is used to insert, modify, and delete records inside database tables.

Unlike DDL, which focuses on the structure of a table, DML focuses on the actual information stored in it.

1. INSERT Command

INSERT is used to add new records to a table.

SQL — INSERT INTO 
INSERT INTO contact_messages
(name, email, message)
VALUES
('Pooja', 'pooja@example.com', 'Hello from my portfolio!');

Here, I specify the column names first and then provide the values in the same order.

2. UPDATE Command

UPDATE is used to change existing records in a table. We generally use WHERE to identify the record that needs to be updated.

SQL — UPDATE 
UPDATE contact_messages
SET message = 'Updated portfolio feedback'
WHERE id = 1;

The SET keyword specifies the new value, while WHERE identifies which record should be changed.

Without a WHERE condition, an UPDATE statement can modify every row in the table. Therefore, I should always check my condition before running it.

3. DELETE Command

DELETE is used to remove records from a table.

SQL — DELETE 
DELETE FROM contact_messages
WHERE id = 1;

This removes the record whose id is 1. The table structure remains unchanged.

If WHERE is omitted, DELETE can remove every row from the table. This is another command that requires careful use.

9.5 DCL — Data Control Language

DCL stands for Data Control Language. It is used to manage permissions and access rights for database users.

In a real application, not every database user should have permission to perform every operation. For example, one user may only need to read information, while another user may need to insert or update records.

1. GRANT Command

GRANT is used to provide privileges to a database user.

SQL — GRANT SELECT 
GRANT SELECT
ON portfolio_contact.contact_messages
TO 'report_user'@'localhost';

This example grants SELECT permission on the specified table to the report_user account. The user account must already exist.

2. REVOKE Command

REVOKE is used to remove privileges that were previously granted to a database user.

SQL — REVOKE SELECT 
REVOKE SELECT
ON portfolio_contact.contact_messages
FROM 'report_user'@'localhost';

This removes the SELECT privilege from the specified user for that table.

9.6 TCL — Transaction Control Language

TCL stands for Transaction Control Language. It is used to manage transactions in a database.

A transaction is a group of database operations that are treated as one logical unit of work. Transactions are especially important when multiple related changes must succeed together.

For example, imagine transferring money from one bank account to another. The amount should be deducted from one account and added to the other. We do not want only one of these operations to succeed.

1. COMMIT Command

COMMIT permanently saves the changes made in the current transaction.

SQL — COMMIT 
START TRANSACTION;

UPDATE accounts
SET balance = balance - 500
WHERE account_id = 1;

UPDATE accounts
SET balance = balance + 500
WHERE account_id = 2;

COMMIT;

In this example, both account updates are part of one transaction. COMMIT saves the transaction's changes.

2. ROLLBACK Command

ROLLBACK is used to undo changes made in the current transaction that have not yet been committed.

SQL — ROLLBACK 
START TRANSACTION;

UPDATE accounts
SET balance = balance - 500
WHERE account_id = 1;

ROLLBACK;

Here, the uncommitted update is rolled back instead of being saved.

3. SAVEPOINT Command

SAVEPOINT creates a named point inside a transaction. It allows us to roll back part of a transaction without undoing all the earlier operations.

SQL — SAVEPOINT 
START TRANSACTION;

UPDATE accounts
SET balance = balance - 500
WHERE account_id = 1;

SAVEPOINT after_first_update;

UPDATE accounts
SET balance = balance + 500
WHERE account_id = 2;

ROLLBACK TO SAVEPOINT after_first_update;

COMMIT;

The second update is undone, while the first update remains part of the transaction and is committed.

9.7 Important Difference Between DDL, DML, and TCL

While learning these categories, I noticed that it is particularly important to understand the difference between changing a table's structure, changing its records, and managing transactions.

Operation Command What It Changes
DDL CREATE Creates a database object.
DDL ALTER Changes the structure of an object.
DDL DROP Removes a database object.
DML INSERT Adds records.
DML UPDATE Changes existing records.
DML DELETE Removes records.
TCL COMMIT Saves the current transaction.
TCL ROLLBACK Undoes uncommitted transaction changes.

One important detail I learned is that COMMIT and ROLLBACK are not limited to INSERT, UPDATE, and DELETE commands. They control transactions containing supported transactional operations.

Also, in MySQL, some statements such as CREATE TABLE, ALTER TABLE, DROP TABLE, and TRUNCATE TABLE cause implicit commits. So, I should not assume that every operation can be undone using ROLLBACK.

9.8 Practising the Categories with My Contact Database

To make these categories easier to remember, I connected them with my own portfolio contact database.

My Practical SQL Command Map

  • DDL: Create the portfolio_contact database and contact_messages table.
  • DQL: Retrieve visitor messages using SELECT.
  • DML: Insert new messages, update records, or delete unwanted records.
  • DCL: Give database users suitable access permissions.
  • TCL: Save or roll back supported transaction changes.

9.9 My Learning Reflection — Understanding the Purpose of Every Command

Earlier, I was learning SQL commands individually. But after grouping them into DDL, DQL, DML, DCL, and TCL, I started understanding their actual responsibilities.

Now I can identify whether I am defining a database structure, retrieving information, manipulating records, controlling permissions, or managing a transaction.

This classification also gives me a better foundation for the next practical steps, where I will create my own database and start working with tables and records.

SETTING RULES FOR RELIABLE DATA · 10

10. SQL Constraints — Setting Rules to Maintain Data Accuracy

While learning how to create tables and insert records, I realized that simply storing data inside a database is not enough. We also need rules to make sure that the information being stored follows the requirements of our application.

For example, imagine a contact form where every visitor must provide a name and email address. What happens if someone submits an empty name? What if two users accidentally receive the same unique ID? What if an order refers to a customer who does not exist?

This is where SQL Constraints become important. Constraints are rules applied to table columns or combinations of columns to control the data that can be stored.

10.1 What Are SQL Constraints?

SQL constraints help maintain the accuracy, validity, and integrity of information stored in a database.

When we define a constraint while creating a table, the database checks whether inserted or updated values follow that rule. If a value violates the constraint, the database rejects the operation.

A Simple Real-World Example

Suppose I am creating a registration table for my website. I want every user to have:

  • A name that cannot be empty.
  • An email address that cannot be repeated.
  • A unique identification number.
  • A default account status when no status is provided.

Instead of depending only on PHP validation, I can also define database constraints to enforce important rules at the database level.

10.2 Common Types of SQL Constraints

The commonly used constraints in MySQL include:

  • NOT NULL: Prevents a column from storing NULL.
  • UNIQUE: Ensures uniqueness of values.
  • PRIMARY KEY: Uniquely identifies each row.
  • FOREIGN KEY: Maintains relationships between tables.
  • CHECK: Validates values against a condition.
  • DEFAULT: Supplies a default value when one is not provided.
  • AUTO_INCREMENT: Automatically generates increasing numeric values in MySQL.

10.3 NOT NULL Constraint

NOT NULL is used when a column must always have a value. It prevents a record from storing NULL in that column.

For example, in my contact form, the visitor's name and message should not be missing. I can apply NOT NULL to these columns.

SQL — NOT NULL 
CREATE TABLE visitors (
    visitor_id INT,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(150),
    message TEXT NOT NULL
);

In this example, name and message cannot contain NULL. However, NOT NULL does not automatically prevent an empty string such as ''. If empty text must also be rejected, we need additional validation.

10.4 UNIQUE Constraint

UNIQUE ensures that duplicate values are not allowed in the constrained column or combination of columns.

For example, if every registered user must have a different email address, I can apply a UNIQUE constraint to the email column.

SQL — UNIQUE 
CREATE TABLE users (
    user_id INT,
    username VARCHAR(100),
    email VARCHAR(150) UNIQUE
);

This prevents duplicate non-NULL email values. In MySQL, a UNIQUE constraint can allow multiple NULL values, depending on the column definition and database rules. If an email is mandatory and unique, we should combine UNIQUE with NOT NULL.

SQL — UNIQUE with NOT NULL 
CREATE TABLE users (
    user_id INT,
    email VARCHAR(150) NOT NULL UNIQUE
);

10.5 PRIMARY KEY Constraint

PRIMARY KEY is used to uniquely identify each record in a table. It combines the requirements of uniqueness and NOT NULL.

A table has one primary key constraint, but that key can consist of one column or multiple columns.

SQL — PRIMARY KEY 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(100),
    age INT
);

Here, student_id uniquely identifies every student. Two records cannot have the same student_id, and the value cannot be NULL.

Composite Primary Key

Sometimes one column is not enough to identify a record. In such situations, we can combine two or more columns to create a composite primary key.

SQL — Composite PRIMARY KEY 
CREATE TABLE student_courses (
    student_id INT,
    course_id INT,

    PRIMARY KEY (student_id, course_id)
);

Here, the combination of student_id and course_id must be unique. A student can select multiple courses, but the same student-course combination cannot be repeated.

10.6 FOREIGN KEY Constraint

FOREIGN KEY creates a relationship between tables. It ensures that a value in one table refers to an existing candidate key value in another table, according to the defined constraint.

For example, imagine that I have a customers table and an orders table. Every order should belong to a valid customer.

SQL — FOREIGN KEY 
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    customer_name VARCHAR(100)
);

CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,

    FOREIGN KEY (customer_id)
    REFERENCES customers(customer_id)
);

In this example, customer_id in the orders table refers to customer_id in the customers table. The foreign key helps prevent orders from referring to customers that do not exist.

Foreign Key Actions

We can also define what happens when a referenced customer is updated or deleted.

SQL — ON DELETE and ON UPDATE 
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,

    FOREIGN KEY (customer_id)
    REFERENCES customers(customer_id)

    ON DELETE CASCADE
    ON UPDATE CASCADE
);
  • CASCADE: Applies the change to related child records.
  • SET NULL: Sets the foreign key value to NULL when allowed.
  • RESTRICT: Prevents an operation that would violate the relationship.
  • NO ACTION: Does not automatically modify related records; enforcement depends on the database system.

10.7 CHECK Constraint

CHECK is used to validate data against a condition. It allows us to define rules about which values are acceptable.

For example, if I am storing student ages, I may want the age to be greater than or equal to 18.

SQL — CHECK 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(100),
    age INT CHECK (age >= 18)
);

This condition prevents values that do not satisfy age >= 18 from being stored.

MySQL supports enforced CHECK constraints from version 8.0.16 onward. In older versions, CHECK expressions could be parsed but not enforced, so version awareness is important.

CHECK with a Range

SQL — CHECK BETWEEN 
CREATE TABLE exam_results (
    result_id INT PRIMARY KEY,
    student_name VARCHAR(100),
    marks INT CHECK (marks BETWEEN 0 AND 100)
);

Here, marks must be between 0 and 100.

10.8 DEFAULT Constraint

DEFAULT supplies a predefined value when an INSERT statement does not provide a value for that column.

Imagine that every new visitor message should initially have a status of "Pending". Instead of inserting this value manually every time, I can define it as a default.

SQL — DEFAULT 
CREATE TABLE contact_messages (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    message TEXT NOT NULL,
    status VARCHAR(20) DEFAULT 'Pending'
);

Now, when I insert a record without specifying status, MySQL uses the default value.

SQL — INSERT Using DEFAULT 
INSERT INTO contact_messages
(name, message)
VALUES
('Pooja', 'Thank you for visiting my portfolio!');

The status of this record will be Pending. If I explicitly insert NULL into a nullable column, the default is not automatically substituted.

10.9 AUTO_INCREMENT in MySQL

AUTO_INCREMENT is a MySQL column attribute that automatically generates a new numeric value when a row is inserted without providing a value for that column.

It is commonly used for identification columns such as user_id, product_id, order_id, or message_id.

SQL — AUTO_INCREMENT 
CREATE TABLE users (
    user_id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(100) NOT NULL
);

Now I can insert users without manually entering user_id.

SQL — INSERT Without the ID 
INSERT INTO users (username)
VALUES ('Pooja');

INSERT INTO users (username)
VALUES ('Aman');

MySQL generates the numeric ID values automatically. AUTO_INCREMENT values are not guaranteed to be continuous: deleted records, failed inserts, and other operations can leave gaps.

10.10 Applying Multiple Constraints Together

In a real project, we often use more than one constraint in the same table. Each constraint protects a different part of the data.

Let's create a users table that combines several constraints in one practical example.

SQL — Combining Constraints 
CREATE TABLE users (
    user_id INT AUTO_INCREMENT PRIMARY KEY,

    username VARCHAR(100) NOT NULL,

    email VARCHAR(150) NOT NULL UNIQUE,

    age INT CHECK (age >= 18),

    status VARCHAR(20) DEFAULT 'Active',

    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

Let's understand the responsibility of each column:

  • user_id: Automatically generated unique identifier.
  • username: Cannot contain NULL.
  • email: Must be provided and must be unique.
  • age: Must satisfy the defined CHECK condition.
  • status: Uses Active when no value is provided.
  • created_at: Stores the current timestamp by default.

10.11 Adding Constraints to an Existing Table

I also learned that constraints do not always need to be defined only when a table is first created. We can add certain constraints later using ALTER TABLE.

Adding a UNIQUE Constraint

SQL — ALTER TABLE with UNIQUE 
ALTER TABLE users
ADD CONSTRAINT unique_username
UNIQUE (username);

Adding a CHECK Constraint

SQL — ALTER TABLE with CHECK 
ALTER TABLE users
ADD CONSTRAINT check_user_age
CHECK (age >= 18);

Adding a FOREIGN KEY

SQL — ALTER TABLE with FOREIGN KEY 
ALTER TABLE orders
ADD CONSTRAINT fk_customer
FOREIGN KEY (customer_id)
REFERENCES customers(customer_id);

One important thing to remember is that existing records must satisfy the new constraint. Otherwise, MySQL may reject the ALTER TABLE operation.

10.12 Constraints vs PHP Validation

While connecting my PHP forms with MySQL, I understood that validation can happen at more than one level.

PHP can validate user input before sending it to the database. MySQL constraints provide another layer of protection when data is inserted or updated.

PHP Validation MySQL Constraints
Checks data before database operations. Checks data at the database level.
Can display friendly error messages to users. Protects stored data from invalid operations.
Can validate complex application-specific rules. Enforces defined database rules consistently.
Works in the application layer. Works in the database layer.

I realized that these two approaches should work together. PHP validation improves the user experience, while database constraints help maintain data integrity even when records are changed through another application or database tool.

10.13 My Learning Reflection — Rules Make Data Reliable

Before learning constraints, I thought that creating a table and inserting values was enough to build a database. Now I understand that a database also needs rules to protect the quality of the information stored inside it.

NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, CHECK, DEFAULT, and AUTO_INCREMENT each solve a different problem. Together, they help me build more reliable database structures.

I can now connect these concepts with my PHP and MySQL projects. For example, when a visitor submits a contact form, I can validate the input in PHP and use suitable database constraints to protect the stored records.

"A good database does not simply accept information; it follows rules that help keep that information trustworthy."

11. Creating a Database in MySQL — Starting My Practical Journey

After understanding SQL commands, their categories, and database constraints, I was ready to start creating my own database. Until now, I had learned what databases are and how they work. Now I wanted to understand how to create one using actual SQL commands.

A database is the foundation where an application can organize and manage its information. Before creating tables or inserting records, we first need a database in which those tables will be stored.

In my PHP and MySQL learning journey, I also worked with a database named portfolio_contact, where I stored visitor messages submitted through my portfolio contact form. This practical experience helped me understand why database creation is an important first step in backend development.

11.1 What Does Creating a Database Mean?

Creating a database means setting up a named container in the database management system where related database objects can be organized.

These objects can include tables, views, indexes, stored procedures, and other database-related elements.

For example, an online shopping application may have a database named shopping_store. Inside it, we can create tables for customers, products, orders, and payments.

11.2 CREATE DATABASE — Our First Database Command

The CREATE DATABASE command is a DDL command. It is used to create a new database in MySQL.

Its basic syntax is:

SQL — CREATE DATABASE Syntax 
CREATE DATABASE database_name;

Here, database_name represents the name we want to assign to our new database.

Let's create a database for a portfolio website:

SQL — Creating My Portfolio Database 
CREATE DATABASE portfolio_contact;

When this statement executes successfully, MySQL creates a database named portfolio_contact.

11.3 Understanding Database Naming Rules

Before creating a database, I also learned that choosing a meaningful name is important. A clear name helps us understand the purpose of the database when working with multiple projects.

Some good database naming practices include:

  • Use meaningful names related to the project.
  • Avoid unnecessary spaces in database names.
  • Use underscores to separate words when helpful.
  • Avoid reserved SQL keywords as names.
  • Keep naming consistent across the project.
  • Follow the naming conventions used by your team or project.

Examples of Database Names

  • portfolio_contact: Portfolio visitor messages.
  • buslink_amloh: Bus schedule and reminder application.
  • school_management: School records and student information.
  • online_store: Products, customers, and orders.

11.4 CREATE DATABASE IF NOT EXISTS

While practising database creation, I learned that running CREATE DATABASE again with the same name can produce an error because the database already exists.

To avoid this situation, MySQL provides the IF NOT EXISTS option.

SQL — IF NOT EXISTS 
CREATE DATABASE IF NOT EXISTS portfolio_contact;

This statement creates the database only if it does not already exist. If the database is already present, MySQL does not create another one.

This is useful when running setup scripts repeatedly. However, IF NOT EXISTS does not update or repair an existing database.

11.5 SHOW DATABASES — Viewing Available Databases

After creating a database, I wanted to check whether it was actually available in MySQL.

The SHOW DATABASES statement displays databases that the current MySQL account has permission to see.

SQL — SHOW DATABASES 
SHOW DATABASES;

The output may contain database names such as:

Example Output 
information_schema
mysql
performance_schema
sys
portfolio_contact

The system databases are maintained by MySQL. Our portfolio_contact database appears alongside them because we created it.

11.6 USE — Selecting a Database

Creating a database does not automatically mean that every following SQL command will operate inside it. We need to select the database we want to work with.

MySQL provides the USE statement for this purpose.

SQL — USE DATABASE 
USE portfolio_contact;

After executing this statement, portfolio_contact becomes the default database for subsequent statements in the current connection, unless another database is selected.

This is important because commands such as CREATE TABLE can now create tables inside the selected database without requiring us to write the database name every time.

11.7 SELECT DATABASE() — Checking the Current Database

Sometimes I may forget which database I have selected. MySQL provides a function called DATABASE() that returns the name of the current default database.

SQL — Checking the Selected Database 
SELECT DATABASE();

If portfolio_contact is currently selected, the result will show that database name.

11.8 DROP DATABASE — Removing a Database

While learning database creation, I also needed to understand how to remove a database when it is no longer required.

The DROP DATABASE command permanently removes a database and its objects.

SQL — DROP DATABASE 
DROP DATABASE portfolio_contact;

We can also use IF EXISTS to avoid an error if the database is not present:

SQL — DROP DATABASE IF EXISTS 
DROP DATABASE IF EXISTS portfolio_contact;

I learned to be especially careful with this command. Dropping a database removes its tables and stored data. It is not the same as simply switching to another database.

11.10 Understanding Character Sets and Collations

While exploring database settings, I came across two additional terms: character set and collation.

A Character Set defines which characters can be stored and how they are encoded.

A Collation defines how text is compared and sorted. For example, a collation can determine whether text comparisons treat uppercase and lowercase letters as equal.

For modern applications, utf8mb4 is a commonly recommended MySQL character set because it supports a wide range of Unicode characters, including emoji.

SQL — Creating a Database with utf8mb4 
CREATE DATABASE portfolio_contact
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;

Here, utf8mb4 defines the character encoding, while utf8mb4_unicode_ci defines the text comparison and sorting behavior.

MySQL also provides other utf8mb4 collations, including newer language-specific and Unicode-based options. The suitable collation depends on the application's language and comparison requirements.

BUILDING MY FIRST DATABASE TABLES · 12

12. Creating Tables in MySQL — Organizing Information Inside a Database

In the previous chapter, I learned how to create a database and select it using the USE statement. But a database alone does not organize individual records. To store information in a structured way, I need to create tables inside it.

While working with my portfolio contact form, I needed a place to store visitor names, email addresses, messages, and submission dates. Instead of storing everything together without a structure, I created a table with separate columns for each type of information.

This helped me understand that table creation is one of the most important steps in designing a relational database.

12.1 What Is a Table in MySQL?

A table is a database object that stores related information in the form of rows and columns.

  • Table: A collection of related records.
  • Column: Defines the type of information we want to store.
  • Row: Represents one complete record.
  • Cell: Contains an individual value at the intersection of a row and column.

Example — A Students Table

student_id student_name age course
1 Pooja 22 BCA
2 Aman 21 BBA
3 Simran 23 BCA

Here, students is the table name. Every column describes one student property, and each row represents a student record.

12.2 CREATE TABLE — The Basic Syntax

The CREATE TABLE statement is a DDL command. It creates a new table inside the currently selected database.

The basic syntax is:

SQL — CREATE TABLE Syntax 
CREATE TABLE table_name (
    column1 datatype,
    column2 datatype,
    column3 datatype
);

Let's understand its parts:

  • CREATE TABLE: Tells MySQL to create a table.
  • table_name: The name assigned to the table.
  • column1, column2: The names of the columns.
  • datatype: Defines the kind of values a column can store.
  • Comma (,): Separates column definitions.
  • Semicolon (;): Marks the end of the SQL statement.

SQL — First Table 
CREATE TABLE visitors (
    id INT,
    name VARCHAR(100),
    email VARCHAR(150),
    message TEXT
);

MySQL creates a table with four columns:

  • id: Stores an integer identification number.
  • name: Stores text up to the defined length.
  • email: Stores an email address as text.
  • message: Stores longer text content.

At this stage, I have created only the structure. The table does not automatically contain visitor records. I will insert records in the upcoming chapters.

12.5 CREATE TABLE IF NOT EXISTS

What happens if I execute the same CREATE TABLE statement again? MySQL may report that the table already exists.

To avoid this error when running a setup script repeatedly, I can use IF NOT EXISTS.

SQL — IF NOT EXISTS 
CREATE TABLE IF NOT EXISTS visitors (
    id INT,
    name VARCHAR(100),
    email VARCHAR(150),
    message TEXT
);

This creates the table only if it does not already exist. It does not modify an existing table or check whether its columns match the new definition.

12.6 Understanding Column Names and Data Types

Every column needs a name and a suitable data type. The data type determines what kind of information can be stored in that column.

For example, an age column should generally store a numeric value, while a name column should store text.

Choosing Suitable Column Names

  • user_id: Identifies a user.
  • first_name: Stores a person's first name.
  • email: Stores an email address.
  • price: Stores a product price.
  • created_at: Stores a creation date and time.
  • is_active: Stores an active or inactive status.

A column name should clearly describe the information it represents. Meaningful naming makes SQL queries easier to understand and maintain.

12.7 Adding Constraints While Creating a Table

I learned in the previous chapter that constraints help maintain data accuracy. We can define them directly inside the CREATE TABLE statement.

SQL — Table with Constraints 
CREATE TABLE users (
    user_id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL UNIQUE,
    status VARCHAR(20) DEFAULT 'Active'
);

Here, the table combines different rules:

  • AUTO_INCREMENT: Generates a numeric ID automatically.
  • PRIMARY KEY: Uniquely identifies each user.
  • NOT NULL: Requires a username and email value.
  • UNIQUE: Prevents duplicate non-NULL email values.
  • DEFAULT: Assigns Active when status is omitted.

12.8 Creating More Than One Table

A real application usually needs multiple tables because different types of information should be organized separately.

For example, a shopping application may need customers, products, and orders tables.

SQL — Customers Table 
CREATE TABLE customers (
    customer_id INT AUTO_INCREMENT PRIMARY KEY,
    customer_name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE
);
SQL — Products Table 
CREATE TABLE products (
    product_id INT AUTO_INCREMENT PRIMARY KEY,
    product_name VARCHAR(150) NOT NULL,
    price DECIMAL(10,2) NOT NULL
);
SQL — Orders Table 
CREATE TABLE orders (
    order_id INT AUTO_INCREMENT PRIMARY KEY,
    customer_id INT NOT NULL,
    order_date DATETIME DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (customer_id)
    REFERENCES customers(customer_id)
);

Notice that the orders table contains customer_id as a foreign key. This connects each order to a customer stored in the customers table.

13. Understanding SQL Data Types — Deciding What Kind of Information a Column Can Store

In the previous chapter, I learned how to create tables using CREATE TABLE. While defining columns, I noticed that every column needs a data type. This made me curious about why MySQL requires us to define the type of information that each column will store.

For example, a visitor's name contains text, age contains a whole number, product price may contain decimal values, and a registration date contains date-related information. Storing all these values in the same way would not be a good database design.

That is why MySQL provides different data types. They help define the nature of data, control valid values, and use storage efficiently.

13.1 What Is a Data Type?

A data type defines what kind of value a column can store. When I create a table, I assign a suitable data type to each column according to the information it represents.

Understanding Through Everyday Examples

  • Name: Text information — VARCHAR.
  • Age: Whole number — INT.
  • Product price: Decimal number — DECIMAL.
  • Date of birth: Date information — DATE.
  • Registration time: Date and time — DATETIME.

Choosing the right data type helps prevent unsuitable values from being stored and makes database operations more meaningful.

13.2 Main Categories of MySQL Data Types

During my learning, I grouped commonly used MySQL data types into three major categories:

  • String Data Types: Used for text and character information.
  • Numeric Data Types: Used for whole numbers, decimal numbers, and other numeric values.
  • Date and Time Data Types: Used for dates, times, and timestamps.

MySQL also provides other specialized types, such as spatial data types and JSON. For now, I am focusing on the three categories I commonly need while building web applications.

13.3 String Data Types — Storing Text Information

String data types are used to store text, characters, names, addresses, descriptions, email addresses, and other textual information.

1. CHAR

CHAR is a fixed-length string data type. It is useful when the stored values usually have a predictable length.

SQL — CHAR Example 
CREATE TABLE country_codes (
    code CHAR(2)
);

Here, code can store values such as IN, US, or UK. CHAR reserves a fixed-length character space for each stored value, subject to MySQL's character-set rules.

2. VARCHAR

VARCHAR is a variable-length string data type. It is commonly used when text values can have different lengths.

SQL — VARCHAR Example 
CREATE TABLE users (
    username VARCHAR(100),
    email VARCHAR(150)
);

A username may contain only a few characters, while an email address may be longer. VARCHAR is useful for storing both within the defined maximum length.

3. TEXT

TEXT is designed for longer text content, such as descriptions, comments, feedback, and messages.

SQL — TEXT Example 
CREATE TABLE feedback (
    visitor_name VARCHAR(100),
    visitor_message TEXT
);

In my portfolio contact form, visitors can write messages of different lengths. TEXT is therefore a useful choice for the message column.

4. TINYTEXT, MEDIUMTEXT and LONGTEXT

MySQL provides different TEXT variations depending on how much text needs to be stored.

Data Type Maximum Length Common Use
TINYTEXT 255 bytes Small text content
TEXT 65,535 bytes Messages and descriptions
MEDIUMTEXT 16,777,215 bytes Larger text documents
LONGTEXT 4,294,967,295 bytes Very large text content

These limits are measured in bytes, not necessarily characters. The number of characters that fit depends on the character set being used.

5. ENUM

ENUM is used when a column should contain one value selected from a predefined list.

SQL — ENUM Example 
CREATE TABLE tasks (
    task_name VARCHAR(100),
    task_status ENUM(
        'Pending',
        'In Progress',
        'Completed'
    )
);

Here, task_status is designed to accept one of the listed values. ENUM is useful for controlled categories, although I should choose it carefully when the available options may change frequently.

6. SET

SET is another string data type. Unlike ENUM, it can store zero or more selected values from a predefined list.

SQL — SET Example 
CREATE TABLE user_preferences (
    preferred_days SET(
        'Monday',
        'Wednesday',
        'Friday'
    )
);

A record can contain multiple selected values, such as Monday and Friday. For complex or frequently changing selections, a separate related table may be a better design.

13.4 Numeric Data Types — Storing Numbers

Numeric data types are used for quantities, ages, identifiers, prices, measurements, and calculations. However, not every number should use the same data type.

1. TINYINT

TINYINT stores a small integer. It can be signed or unsigned.

SQL — TINYINT Example 
CREATE TABLE attendance (
    attendance_count TINYINT UNSIGNED
);

An unsigned TINYINT stores values from 0 to 255. It can be useful for small counts or compact numeric values.

2. SMALLINT

SMALLINT stores a larger range of whole numbers than TINYINT.

SQL — SMALLINT Example 
CREATE TABLE exam_results (
    total_marks SMALLINT UNSIGNED
);

It may be useful for storing values such as total marks when the expected range fits the selected type.

3. INT or INTEGER

INT is one of the most commonly used integer data types. It stores whole numbers without decimal fractions.

SQL — INT Example 
CREATE TABLE students (
    student_id INT,
    age INT
);

INT is commonly used for identification numbers, counts, and other whole-number values.

4. BIGINT

BIGINT is used when the expected integer values are much larger than the range supported by INT.

SQL — BIGINT Example 
CREATE TABLE large_records (
    record_id BIGINT
);

It is useful for systems that may generate very large identifiers or store large whole-number quantities.

5. DECIMAL

DECIMAL stores exact fixed-point numeric values. It is especially useful for financial information, prices, and amounts where decimal accuracy matters.

SQL — DECIMAL Example 
CREATE TABLE products (
    product_id INT,
    product_price DECIMAL(10,2)
);

In DECIMAL(10,2):

  • 10: Maximum total number of digits.
  • 2: Number of digits after the decimal point.

For example, 12345678.90 contains ten digits in total, including two digits after the decimal point.

6. FLOAT and DOUBLE

FLOAT and DOUBLE are approximate floating-point numeric types. They are suitable for scientific calculations and measurements where approximate values are acceptable.

SQL — FLOAT and DOUBLE 
CREATE TABLE measurements (
    temperature FLOAT,
    distance DOUBLE
);

FLOAT generally provides less precision than DOUBLE. Since floating-point values are approximate, I should prefer DECIMAL for prices and financial amounts.

13.5 Signed and Unsigned Numbers

While exploring integer data types, I came across two important terms: SIGNED and UNSIGNED.

  • SIGNED: Allows negative and positive values, including zero.
  • UNSIGNED: Allows zero and positive values only.
SQL — Signed and Unsigned 
CREATE TABLE inventory (
    temperature INT,
    available_stock INT UNSIGNED
);

Temperature may sometimes be negative, so a signed integer can be appropriate. Available stock should not be negative, so an unsigned integer may be suitable.

13.6 Date and Time Data Types

Many applications need to remember when something happened. For example, when a visitor submitted a contact form, when a user registered, or when a bus reminder was created.

MySQL provides special date and time data types for storing this information.

1. DATE

DATE stores a calendar date without a time component.

SQL — DATE Example 
CREATE TABLE students (
    student_name VARCHAR(100),
    date_of_birth DATE
);

A DATE value is commonly written in YYYY-MM-DD format, such as 2004-08-15.

2. TIME

TIME stores a time value. It can represent a time of day or a time interval.

SQL — TIME Example 
CREATE TABLE bus_timings (
    bus_name VARCHAR(100),
    departure_time TIME
);

For a bus schedule, departure_time could store a value such as 08:30:00.

3. DATETIME

DATETIME stores both a date and a time. It is useful when an application needs to record a specific date and clock time.

SQL — DATETIME Example 
CREATE TABLE appointments (
    appointment_id INT,
    appointment_at DATETIME
);

A DATETIME value can look like 2026-11-19 10:30:00.

4. TIMESTAMP

TIMESTAMP also stores date and time information. It is often used for tracking when a record was created or updated.

SQL — TIMESTAMP Example 
CREATE TABLE messages (
    message_id INT AUTO_INCREMENT PRIMARY KEY,
    message TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CURRENT_TIMESTAMP provides the current date and time when the record is inserted, if the column value is not explicitly supplied.

One important difference is that TIMESTAMP values are handled with MySQL's session time-zone conversion, while DATETIME stores a date and time without that automatic time-zone conversion.

5. YEAR

YEAR stores a year value. It can be useful when only the year is needed rather than a complete date.

SQL — YEAR Example 
CREATE TABLE education (
    qualification VARCHAR(100),
    completion_year YEAR
);

14. Selecting a Database in MySQL — Choosing Where My SQL Commands Will Work

In the previous chapters, I learned how to create databases, create tables, and define different data types. But while practicing MySQL, I realized that creating a database and selecting a database are two different operations.

A MySQL server can contain many databases. For example, I may have one database for my portfolio website, another for my BusLink Amloh project, and another for practice. Before working with tables, I need to tell MySQL which database I want to use.

This is where the USE statement becomes important.

14.1 What Does Selecting a Database Mean?

Selecting a database means setting the default database for the current MySQL connection. After selecting it, I can refer to its tables by their names without writing the database name every time.

For example, imagine that my MySQL server contains:

My Databases

  • portfolio_contact: Stores portfolio visitor messages.
  • buslink_amloh: Stores bus schedules and reminder information.
  • student_records: Stores student information for practice.

If I want to work with portfolio visitor messages, I should select portfolio_contact first.

14.2 USE — Selecting a Database

The USE statement tells MySQL which database should be treated as the default database for the current connection.

SQL — USE Syntax 
USE database_name;

For example, to select my portfolio database:

SQL — Selecting Portfolio Database 
USE portfolio_contact;

If the database exists and I have permission to access it, MySQL selects it. Now I can work with its tables directly.

14.3 What Happens After Using USE?

Once I execute USE portfolio_contact, I can create or access tables inside that database without repeatedly writing its full database name.

SQL — Working Inside the Selected Database

-- Create a table
CREATE TABLE IF NOT EXISTS visitors (

);

Notice that I used only the table name in CREATE TABLE and DESCRIBE. MySQL knows which database to use because I selected it earlier.

14.4 SELECT DATABASE() — Checking the Current Database

Sometimes I may forget which database is currently selected. Instead of guessing, I can ask MySQL to display the name of the current default database.

For this, MySQL provides the DATABASE() function.

SQL — Checking Current Database

If I previously executed USE portfolio_contact, the result will be:

Example Output

-----------------

14.5 Switching Between Multiple Databases

A developer may work on several projects using the same MySQL server. In that situation, switching between databases is simple: execute USE again with the new database name.

15. Creating Columns and Inserting Data — Giving Life to My Database Tables

In the previous chapters, I learned how to create a database, define tables, choose suitable data types, and select the database in which I want to work.

But I noticed something important: creating a table does not automatically fill it with information. A table may have columns such as id, name, email, and message, but those columns remain empty until I insert actual records.

While building my portfolio contact form, I needed to store information submitted by visitors. This made me understand why inserting data is one of the most essential operations in database management.

15.1 Understanding Columns and Records

Before inserting information, I should understand the relationship between columns and records.

  • Column: Defines what type of information a table stores.
  • Record: Represents one complete entry in a table.
  • Value: The actual information stored inside a column for a particular record.

Example — Visitors Table

id name email
1 Pooja pooja@example.com
2 Aman aman@example.com

Here, id, name, and email are columns. The information belonging to Pooja makes one record, while Aman makes another record.

15.2 INSERT INTO — The Command Used to Add Data

MySQL provides the INSERT INTO statement to add new records into an existing table.

INSERT is a DML (Data Manipulation Language) command because it changes the data stored inside a table.

The basic syntax is:

SQL — INSERT INTO Syntax 
INSERT INTO table_name (column1, column2, column3)
VALUES (value1, value2, value3);

Let's understand each part:

  • INSERT INTO: Tells MySQL that I want to add a new record.
  • table_name: Specifies the table where the record should be stored.
  • Column list: Specifies which columns will receive values.
  • VALUES: Introduces the actual values to insert.
  • Semicolon (;): Marks the end of the SQL statement.

15.3 Creating a Table for Practice

Before inserting records, I need an existing table. Let's create a simple students table.

SQL — Creating Students Table 
CREATE TABLE students (
    student_id INT AUTO_INCREMENT PRIMARY KEY,
    student_name VARCHAR(100) NOT NULL,
    email VARCHAR(150),
    course VARCHAR(50)
);

I have created four columns. The student_id column is an automatically generated primary key, while the remaining columns store student information.

15.4 Inserting My First Record

Now I can add my first student record. I will provide values for student_name, email, and course.

SQL — First INSERT Statement 
INSERT INTO students (student_name, email, course)
VALUES ('Pooja', 'pooja@example.com', 'BCA');

Notice that I did not provide student_id. MySQL automatically generates its value because the column uses AUTO_INCREMENT.

The record is now stored in the students table.

15.5 Why Do We Write Column Names?

One important thing I learned is that specifying column names makes an INSERT statement clearer and safer.

SQL — Inserting with Column Names 
INSERT INTO students (student_name, email, course)
VALUES ('Aman', 'aman@example.com', 'BBA');

Here, I explicitly tell MySQL which value belongs to which column. The values must match the order of the columns in the column list.

This approach is especially helpful when a table has many columns or when some columns have default values.

15.6 Inserting Data Without Writing All Column Names

MySQL also allows an INSERT statement without an explicit column list. However, in this case, I must provide values for every column in the table in the exact order in which the columns were defined.

SQL — INSERT Without Column Names

16. Inserting Multiple Rows in MySQL — Adding Several Records with One Query

In the previous chapter, I learned how to insert a single record into a table using INSERT INTO. I understood how to specify column names, provide values, and store different types of information.

But while imagining a real application, I realized that a table rarely contains just one record. For example, a student management system may contain hundreds of students, and my portfolio website may receive messages from many visitors.

Writing a separate INSERT statement for every record would make my SQL code unnecessarily long. Fortunately, MySQL allows me to insert multiple rows in a single INSERT statement.

16.1 What Is Multiple-Row Insertion?

Multiple-row insertion means adding two or more records into the same table using one INSERT INTO statement.

Instead of executing separate statements, I can provide multiple value groups separated by commas.

16.2 Basic Syntax for Inserting Multiple Rows

The basic syntax is:

SQL — Multiple INSERT Syntax 
INSERT INTO table_name (column1, column2, column3)
VALUES
(value1, value2, value3),
(value4, value5, value6),
(value7, value8, value9);

Let's understand how this syntax works:

  • INSERT INTO: Specifies the table where records will be added.
  • Column list: Defines the columns that receive values.
  • VALUES: Introduces the records to insert.
  • Parentheses ( ): Each pair contains the values for one record.
  • Comma (,): Separates one record's value group from the next.
  • Semicolon (;): Ends the complete SQL statement.

SQL — Inserting Three Students

('Aman', 'aman@example.com', 'BBA'),

16.12 Understanding INSERT Statement Errors

While practicing multiple-row insertion, I also need to understand common mistakes that may cause a query to fail.

18. Renaming Columns and Filtering Data — Making Database Results More Meaningful

In the previous chapter, I learned how to retrieve information from MySQL tables using the SELECT statement. But while working with query results, I realized that sometimes the original column names are not descriptive enough for the output I want to display.

For example, a database column named student_name is understandable to a developer, but I may want its heading to appear as Student Name in my result. Similarly, I may not always need every record stored in a table. I may want to retrieve only the records that match a particular condition.

This is where column aliases and the WHERE clause become useful.

18.1 What Is a Column Alias?

An alias is a temporary name given to a column or expression in the output of a SQL query. It helps make query results more readable and meaningful.

MySQL provides the AS keyword to assign an alias.

SQL — Basic Alias Syntax 
SELECT column_name AS alias_name
FROM table_name;

Here:

  • SELECT: Specifies the column to retrieve.
  • AS: Introduces the temporary alias.
  • alias_name: The new heading shown in the result.
  • FROM: Specifies the source table.

18.2 Renaming a Column Using AS

Suppose I have a students table with a column named student_name. I want the result to display the heading Student Name instead.

SQL — Renaming a Column 
SELECT student_name AS "Student Name"
FROM students;

The query displays Student Name as the result heading instead of student_name.

An important thing I learned is that an alias does not permanently rename the actual database column. It changes only the column heading in that query's result.

18.3 Using AS with Multiple Columns

I can assign different aliases to multiple columns in the same SELECT statement.

SQL — Multiple Column Aliases 
SELECT
    student_name AS "Student Name",
    course AS "Course Name",
    email AS "Email Address"
FROM students;

Now the output becomes easier to understand because each column has a meaningful heading.

18.4 Using an Alias Without AS

I also learned that MySQL allows me to write a column alias without using the AS keyword.

SQL — Alias Without AS 
SELECT student_name "Student Name"
FROM students;

Both forms are valid in MySQL. However, I prefer using AS because it makes the query easier to read.

18.5 Using Aliases with Calculations

Aliases are also useful when I perform calculations in SQL. Instead of showing an expression as a column heading, I can provide a meaningful name.

Now let's understand another important part of SQL. When I retrieve all records using SELECT *, MySQL returns every row from the selected table.

SQL — WHERE Syntax

Operator Meaning

!= or <> Not equal to

< Less than
>= Greater than or equal to
<= Less than or equal to

SELECT *

19. SQL Operators and Conditions — Teaching My Database How to Make Decisions

While learning SQL, I realized that retrieving data becomes more powerful when I can describe exactly what information I need. A database may contain hundreds or thousands of records, but my application may require only a few records that satisfy particular conditions.

SQL operators help me create these conditions. They allow MySQL to compare values, combine conditions, perform calculations, and evaluate logical expressions.

19.1 What Is an SQL Operator?

An operator is a special symbol or keyword used to perform an operation on one or more values. In SQL, operators help me compare data, perform mathematical calculations, and build logical conditions.

For example:

SQL — Basic Operators

SELECT 20 - 5 AS subtraction;

SELECT 10 * 2 AS multiplication;

SELECT 20 / 4 AS division;

MySQL evaluates these expressions and returns their results.

19.5 Understanding Logical Operators

Logical operators become useful when I need to combine more than one condition. The three main logical operators are AND, OR, and NOT.

AND — All Conditions Must Be True

AND returns TRUE only when all connected conditions are TRUE.

SQL — AND Example 
SELECT *
FROM students
WHERE course = 'BCA'
AND marks >= 60;

A record must satisfy both conditions:

  • The course must be BCA.
  • The marks must be at least 60.

OR — At Least One Condition Must Be True

OR returns TRUE when at least one of the connected conditions is TRUE.

SQL — OR Example 
SELECT *
FROM students
WHERE course = 'BCA'
OR course = 'BBA';

A student can belong to either BCA or BBA to appear in the result.

NOT — Reversing a Condition

NOT reverses the logical result of a condition.

SQL — NOT Example 
SELECT *
FROM students
WHERE NOT (marks >= 60);

This query retrieves records for which the condition marks >= 60 is not TRUE. With ordinary non-NULL marks, these are the students scoring below 60. A NULL marks value does not pass this condition.

19.9 Understanding Operator Precedence

This was one of the most important concepts I needed to understand when writing complex SQL conditions. When a query contains multiple operators, MySQL follows operator precedence to decide which operation should be evaluated first.

For example, AND has higher logical precedence than OR. Therefore, MySQL evaluates AND before OR unless parentheses change the grouping.

SQL — Understanding Precedence 
SELECT *
FROM students
WHERE course = 'BCA'
OR course = 'BBA'
AND marks >= 60;

MySQL interprets the condition as:

course = 'BCA' OR (course = 'BBA' AND marks >= 60)

This means:

  • Every BCA student can match the first condition.
  • A BBA student must also have at least 60 marks.

If I want both courses to require at least 60 marks, I should use parentheses.

SQL — Correct Grouping with Parentheses 
SELECT *
FROM students
WHERE (course = 'BCA' OR course = 'BBA')
AND marks >= 60;

Now the marks condition applies to both courses. Parentheses make the intended logic clear and prevent unexpected results.

20. Pattern Matching and Regular Expressions — Searching Beyond Exact Values

While learning SQL, I realized that sometimes I do not know the complete value stored in a database. I may remember only the first letter of a student's name, a few characters from an email address, or one particular word from a visitor's message.

In such situations, searching with the equality operator (=) is not always enough. I need a way to search for values that match a particular pattern.

MySQL provides LIKE and REGEXP for pattern matching. These operators help me search text using wildcards and regular expressions.

20.1 What Is Pattern Matching?

Pattern matching means searching for data according to a specified pattern instead of requiring an exact match.

For example, suppose my students table contains these names:

Sample Student Records

student_id student_name
1 Pooja
2 Priya
3 Aman
4 Simran
5 Parul

If I want to find all students whose names begin with P, I do not need to write a separate condition for every name. I can use a pattern.

20.2 Understanding the LIKE Operator

LIKE is a SQL operator used to search for a specified pattern in a character string.

It is commonly used with the WHERE clause.

SQL — LIKE Syntax 
SELECT column_name
FROM table_name
WHERE column_name LIKE 'pattern';

The pattern is generally written inside single quotes. MySQL compares the column values with that pattern and returns the matching records.

20.3 Understanding the Percentage Symbol (%)

The percentage symbol (%) is one of the most important wildcards used with LIKE.

It represents zero or more characters. This means it can match an empty sequence, a single character, or many characters.

SQL — Percentage Wildcard 
SELECT *
FROM students
WHERE student_name LIKE 'P%';

This query finds names beginning with P, such as Pooja, Priya, and Parul.

Now let's understand how the position of % changes the search.

20.4 Searching Names Beginning with a Letter

If I want names that start with the letter P, I write P followed by the percentage symbol.

SQL — Starts With P 
SELECT *
FROM students
WHERE student_name LIKE 'P%';

Possible matching values:

  • Pooja
  • Priya
  • Parul

20.5 Searching Names Ending with a Letter

If I want to find names ending with the letter a, I place % before the letter.

SQL — Ends With A 
SELECT *
FROM students
WHERE student_name LIKE '%a';

The percentage symbol allows any number of characters before the final a.

20.6 Searching for Text Anywhere in a Value

Sometimes I want to find a particular sequence of characters anywhere inside a value. In that case, I place % on both sides.

SQL — Contains a Pattern 
SELECT *
FROM students
WHERE student_name LIKE '%oo%';

This query finds names containing the character sequence oo anywhere in the name.

20.7 Understanding the Underscore Wildcard (_)

The underscore (_) wildcard represents exactly one character.

Unlike %, which can match zero or more characters, _ must match one character at its position.

SQL — Underscore Wildcard 
SELECT *
FROM students
WHERE student_name LIKE 'P_oja';

This pattern can match Pooja because the underscore represents the second character.

Let's understand another example:

SQL — Multiple Underscores 
SELECT *
FROM students
WHERE student_name LIKE 'P____';

Here, P is followed by exactly four characters. Therefore, the pattern matches five-character names beginning with P.

20.8 Difference Between % and _

Both symbols are wildcards, but they work differently.

Wildcard Meaning Example
% Zero or more characters P%
_ Exactly one character P_

For example, P% can match P, Pooja, or Priya, while P_ matches only values containing P followed by exactly one character.

20.9 Combining Wildcards

I can combine % and _ in one pattern to create more specific searches.

SQL — Combined Wildcards 
SELECT *
FROM students
WHERE student_name LIKE 'P_o%';

This pattern requires the name to begin with P, followed by exactly one character, then o, followed by zero or more characters.

20.10 Using NOT LIKE

LIKE finds values that match a pattern. NOT LIKE does the opposite by returning values that do not match the specified pattern.

SQL — NOT LIKE Example 
SELECT *
FROM students
WHERE student_name NOT LIKE 'P%';

This query retrieves student names that do not begin with P.

20.11 Searching Text Using LIKE with AND and OR

I can combine pattern matching with logical operators. For example, I may want names beginning with P or names ending with a.

SQL — LIKE with OR 
SELECT *
FROM students
WHERE student_name LIKE 'P%'
OR student_name LIKE '%a';

I can also use AND when both patterns must match.

SQL — LIKE with AND 
SELECT *
FROM students
WHERE student_name LIKE 'P%'
AND student_name LIKE '%a';

This query retrieves names that begin with P and end with a.

20.12 What Are Regular Expressions?

After learning LIKE, I wanted to explore more advanced text searching. LIKE is useful for simple wildcard patterns, but sometimes I need to search according to more detailed rules.

This is where Regular Expressions, commonly called RegEx or Regex, become useful.

A regular expression is a sequence of characters that describes a search pattern. It can represent rules such as:

  • Find values beginning with a particular letter.
  • Find values ending with a particular character.
  • Find values containing digits.
  • Find values containing a particular sequence.
  • Find values that follow a specific character pattern.

20.13 Understanding REGEXP in MySQL

MySQL provides REGEXP and RLIKE as regular-expression matching operators. They are commonly used with WHERE.

SQL — REGEXP Syntax 
SELECT column_name
FROM table_name
WHERE column_name REGEXP 'pattern';

REGEXP checks whether the value matches the specified regular expression.

20.14 Understanding the Caret Symbol (^)

One important regular-expression symbol is the caret (^). In a regular expression, when used at the beginning of a pattern, it represents the beginning of the string.

For example, if I want to find student names beginning with P, I can write:

SQL — REGEXP with Caret (^) 
SELECT *
FROM students
WHERE student_name REGEXP '^P';

The caret tells MySQL that P must appear at the beginning of the value.

It is important to understand that the meaning of ^ depends on its position. At the beginning of a regular-expression pattern it anchors the start; inside a bracket expression such as [^a], it means negation.

20.15 Searching Values Ending with a Character Using ($)

The dollar symbol ($) represents the end of a string in a regular expression.

SQL — REGEXP with Dollar ($) 
SELECT *
FROM students
WHERE student_name REGEXP 'a$';

This query finds names ending with the letter a.

20.16 Understanding the Dot Symbol (.)

In regular expressions, a dot (.) generally represents any single character, except a line terminator under the default matching behavior.

SQL — Dot in REGEXP 
SELECT *
FROM students
WHERE student_name REGEXP '^P.oja$';

Here, the dot represents exactly one character between P and oja.

20.17 Understanding Character Sets [ ]

Square brackets allow me to specify a set of characters. The pattern matches any one character from the given set at that position.

SQL — Character Set 
SELECT *
FROM students
WHERE student_name REGEXP '^[PS]';

This query retrieves names beginning with either P or S.

20.18 Understanding Character Ranges

A hyphen inside a character set can specify a range. For example, [A-Z] represents uppercase English letters, while [0-9] represents digits.

SQL — Character Ranges 
-- Values beginning with an uppercase letter
SELECT *
FROM students
WHERE student_name REGEXP '^[A-Z]';

-- Values containing a digit
SELECT *
FROM students
WHERE student_name REGEXP '[0-9]';

20.19 Understanding the Plus (+) Symbol

The plus symbol means one or more occurrences of the preceding expression.

SQL — Plus Quantifier 
SELECT *
FROM students
WHERE student_name REGEXP 'P+o';

This pattern matches one or more consecutive P characters followed by o.

20.20 Understanding the Asterisk (*) in Regular Expressions

In a regular expression, the asterisk means zero or more occurrences of the preceding expression. It is different from the SQL SELECT * symbol.

SQL — Asterisk Quantifier 
SELECT *
FROM students
WHERE student_name REGEXP 'Po*ja';

The regular-expression pattern allows zero or more o characters between P and j.

20.21 Understanding the Question Mark (?)

The question mark means that the preceding expression is optional. It can appear zero or one time.

SQL — Optional Character 
SELECT *
FROM students
WHERE student_name REGEXP '^Colou?r$';

This pattern can match both Colour and Color. The letter u is optional.

20.22 Understanding Curly Braces { }

Curly braces are used to specify how many times the preceding expression should occur.

SQL — Repetition Quantifiers 
-- Exactly three digits
SELECT *
FROM students
WHERE phone REGEXP '^[0-9]{3}$';

-- Between two and four digits
SELECT *
FROM students
WHERE phone REGEXP '^[0-9]{2,4}$';

The first pattern requires exactly three digits. The second allows two, three, or four digits.

20.23 Difference Between LIKE and REGEXP

Both operators help me search text, but their pattern systems are different.

LIKE REGEXP
Uses % and _ wildcards. Uses regular-expression syntax.
Best for simple text patterns. Useful for more detailed patterns.
Uses LIKE keyword. Uses REGEXP or RLIKE.
Can search beginnings, endings, and contained text. Can describe character sets, ranges, repetitions, and anchors.

20.24 MySQL REGEXP Version and Case Sensitivity

I also learned that MySQL's regular-expression implementation depends on the version.

  • MySQL 8.0 uses the ICU regular-expression library.
  • Older MySQL versions used a different regular-expression implementation, so some pattern behavior may differ.
  • REGEXP matching is generally case-sensitive or case-insensitive according to the collation of the expression and string.
  • MySQL 8.0 also provides REGEXP_LIKE() for explicit matching options.
SQL — REGEXP_LIKE()

SELECT *
FROM students
WHERE REGEXP_LIKE(student_name, '^pooja$', 'i');

-- Case-sensitive matching
SELECT *
FROM students
WHERE REGEXP_LIKE(student_name, '^Pooja$', 'c');

The third argument specifies matching behavior. The i option requests case-insensitive matching, while c requests case-sensitive matching.

21.1 What Is ORDER BY?

ORDER BY is an SQL clause used to arrange the rows returned by a query according to one or more columns. It allows me to display information in ascending or descending order.

  • DESC: Arranges values in descending order.

21.2 Understanding ASC — Ascending Order

ASC stands for ascending. It arranges values from lower to higher according to the data type.

  • Text: alphabetically according to the column collation.
  • Dates: earliest to latest.

SELECT *
FROM students
ORDER BY student_name ASC;

This query arranges student names alphabetically according to the applicable collation.

Another example is arranging marks from lowest to highest:

SQL — Marks in Ascending Order 
SELECT *
FROM students

SQL — Descending Order 
SELECT *
FROM students
ORDER BY marks DESC;

This query displays students with the highest marks first.

Similarly, I can arrange dates from newest to oldest:

SQL — Latest Records First 
SELECT *
FROM contact_messages
ORDER BY created_at DESC;

This is useful for my portfolio because I may want to see recently submitted visitor messages before older messages.

DISTINCT affects the returned result. It does not delete duplicate records from the original table.

21.14 What Is NULL?

Now I wanted to understand another important database concept: NULL.

NULL represents a missing, unknown, or unavailable value. It does not mean zero, an empty string, or a blank space.

For example, if a student has not provided an email address, the email column may contain NULL.

Example — Understanding Different Values

0 Numeric zero.
'' Empty string.

I cannot use the normal equality operator to check whether a column contains NULL.

Instead, I use IS NULL.

SQL — IS NULL

FROM students

If I want records where email contains a non-NULL value, I can use IS NOT NULL.

SQL — IS NOT NULL 
SELECT *
FROM students

This query excludes records where email is NULL. An empty string is still a non-NULL value, so it can appear in this result.

21.17 Why NULL Cannot Be Compared Using =

While learning SQL, I discovered that NULL follows special comparison rules. A normal comparison involving NULL usually produces UNKNOWN rather than TRUE or FALSE.

SQL — Incorrect and Correct NULL Checking 
-- Incorrect way to check NULL
SELECT *
FROM students
WHERE email = NULL;

-- Correct way
SELECT *
FROM students
WHERE email IS NULL;

SQL uses three-valued logic:

  • TRUE — The condition is satisfied.
  • FALSE — The condition is not satisfied.
  • UNKNOWN — The result cannot be determined because of NULL.

21.18 Understanding NULL with NOT

NULL also affects logical conditions. For example, NOT UNKNOWN remains UNKNOWN.

SQL — NULL and Logical Conditions 
SELECT *
FROM students
WHERE NOT (email = 'student@example.com');

A record with a NULL email does not pass this WHERE condition because its comparison result is UNKNOWN, and NOT UNKNOWN is still UNKNOWN.

If I want to include missing email values as well, I should explicitly add an IS NULL condition.

SQL — Including NULL Values 
SELECT *
FROM students
WHERE email <> 'student@example.com'
OR email IS NULL;

21.19 Sorting NULL Values

Another interesting point is how MySQL handles NULL values while sorting.

In ascending order, NULL values generally appear before non-NULL values. In descending order, they generally appear after non-NULL values.

SQL — Sorting with NULL Values

SELECT *
FROM students
ORDER BY email ASC;

-- NULL values appear last
SELECT *
FROM students
ORDER BY email DESC;

This is useful to understand when a column contains both available and missing values.

22. LIMIT and OFFSET — Controlling How Many Records We Retrieve

In the previous chapter, I learned how to arrange database records using ORDER BY, retrieve unique values using DISTINCT, and handle missing values using NULL.

But I started thinking about a practical situation. What happens when my database contains hundreds, thousands, or even millions of records?

If I retrieve every record at once, the application may need to process and display a huge amount of information. This can make the user experience difficult, especially when a website needs to show only a few records at a time.

This is where LIMIT and OFFSET become useful. They help me control how many rows a SELECT query returns and where the returned portion begins.

22.1 What Is LIMIT?

LIMIT is an SQL clause used to restrict the number of rows returned by a query.

For example, if my students table contains 100 records but I only want to display the first five, I can use LIMIT 5.

SQL — LIMIT Syntax 
SELECT column_name
FROM table_name
LIMIT number_of_rows;

Here, number_of_rows specifies the maximum number of rows I want the query to return.

22.2 Retrieving the First Five Records

Suppose I want to retrieve only five student records from my students table.

SQL — LIMIT 5 
SELECT *
FROM students
LIMIT 5;

This query returns a maximum of five rows. However, because I have not specified ORDER BY, I should not assume that these will always be the same five records.

To retrieve the five lowest student IDs, I can explicitly arrange the records first.

SQL — First Five IDs 
SELECT *
FROM students
ORDER BY student_id ASC
LIMIT 5;

22.3 Retrieving the Latest Five Records

I can also combine LIMIT with ORDER BY to retrieve the latest records.

SQL — Latest Five Records 
SELECT *
FROM contact_messages
ORDER BY created_at DESC
LIMIT 5;

This query first arranges contact messages from newest to oldest and then returns only five rows.

If multiple messages have the same created_at value, their relative order is not guaranteed. For more consistent results, I can use a unique ID as a secondary sorting column.

SQL — Stable Sorting with LIMIT 
SELECT *
FROM contact_messages
ORDER BY created_at DESC, id DESC
LIMIT 5;

22.4 What Is OFFSET?

LIMIT controls how many rows I want to retrieve. But sometimes I do not want to begin with the first record.

For example, if I have already displayed the first five records, I may want to skip those records and retrieve the next five.

OFFSET specifies how many rows should be skipped before MySQL begins returning the requested rows.

SQL — LIMIT with OFFSET Syntax 
SELECT column_name
FROM table_name
LIMIT number_of_rows OFFSET number_to_skip;

22.5 Skipping the First Five Records

Suppose I want to skip the first five student records and retrieve the next five.

SQL — OFFSET 5 
SELECT *
FROM students
ORDER BY student_id ASC
LIMIT 5 OFFSET 5;

Here:

  • ORDER BY student_id ASC: Arranges records by ID.
  • LIMIT 5: Returns a maximum of five records.
  • OFFSET 5: Skips the first five records.

In simple words, MySQL skips five rows and then returns the next five rows from the ordered result.

MySQL also supports a comma-separated LIMIT syntax. In this format, the first number represents the offset and the second number represents the row count.

SQL — Comma-Separated LIMIT

22.16 How LIMIT and OFFSET Work in PHP Applications

Since I am learning how to connect PHP with MySQL, I wanted to understand how pagination can be implemented in a real application.

    ? max(1, (int) $_GET['page'])
    : 1;

    FROM contact_messages

    ORDER BY created_at DESC, id DESC

}

?>

I should also validate the requested page number and make sure the application handles database errors and output formatting correctly.

22.17 Calculating the Total Number of Pages

Pagination also needs to know how many pages are available.

For this, I first count the total matching records. Then I divide that count by the number of records I want to display per page.

Total Pages = CEIL(Total Records / Records Per Page)

For example, if I have 45 approved feedback messages and want to display 10 per page:

Total Pages = CEIL(45 / 10) = 5

I can calculate the total records using COUNT(*).

SQL — Counting Matching Records 
SELECT COUNT(*) AS total_records
FROM contact_messages
WHERE is_approved = 2;

The PHP application can use this count to calculate the total number of pages and display navigation links such as Previous, Next, and page numbers.

22.18 A Note About Large OFFSET Values

LIMIT and OFFSET are easy to understand and useful for ordinary pagination. However, I also learned that very large OFFSET values can become inefficient.

For example, if a user requests page 10,000, MySQL may need to scan and skip a large number of rows before returning the requested records.

In applications with very large datasets, developers sometimes use keyset pagination (also called cursor-based pagination).

SQL — Basic Keyset Pagination Example 
SELECT id, name, message, created_at
FROM contact_messages
WHERE id < ?
ORDER BY id DESC
LIMIT 10;

Here, the question mark represents the last ID received on the previous page. This example assumes IDs are unique and the application is navigating in descending ID order.

Keyset pagination is not the same as OFFSET. Instead of counting how many rows to skip, it continues from a known position in the data.

23. Aggregate Functions — Calculating and Summarising Data

In the previous chapters, I learned how to retrieve records using SELECT, filter them using WHERE, arrange them using ORDER BY, and control the number of returned rows using LIMIT and OFFSET.

But while working with database records, I realised that sometimes I do not need to display every individual record. Instead, I need to understand the information stored inside those records.

For example, if my students table contains marks of 100 students, I may want to know the highest marks, lowest marks, or average marks without calculating everything manually.

Similarly, in my portfolio database, I may want to count how many contact messages have been received or how many messages have been approved.

SQL provides special functions for performing these calculations. These are called Aggregate Functions.

23.1 What Are Aggregate Functions?

Aggregate Functions perform calculations on a collection of rows and return a single summary value for the selected group of records.

They help me summarise large amounts of data into meaningful results.

The commonly used aggregate functions in MySQL are:

  • COUNT(): Counts rows or non-NULL values.
  • SUM(): Calculates the total of numeric values.
  • AVG(): Calculates the average of numeric values.
  • MIN(): Finds the minimum value.
  • MAX(): Finds the maximum value.

23.2 Understanding COUNT()

COUNT() is used to count records or non-NULL values in a selected column.

Suppose I have a students table containing 50 student records. If I want to know how many students are stored in the table, I can use COUNT().

SQL — COUNT Syntax 
SELECT COUNT(column_name)
FROM table_name;

There are three useful ways to understand COUNT().

1. COUNT(*) — Counting All Rows

COUNT(*) counts all rows returned by the query, including rows containing NULL values in individual columns.

SQL — Count All Students 
SELECT COUNT(*)
FROM students;

If the table contains 50 rows, the result will be 50.

2. COUNT(column_name) — Counting Non-NULL Values

COUNT(column_name) counts only those rows where the selected column is not NULL.

SQL — Count Available Email Addresses 
SELECT COUNT(email)
FROM students;

If the students table contains 50 records but only 45 students have an email address, this query returns 45.

3. COUNT(DISTINCT column_name)

COUNT(DISTINCT column_name) counts the number of unique non-NULL values in a column.

SQL — Count Unique Courses 
SELECT COUNT(DISTINCT course)
FROM students;

This query counts how many different course names are stored in the students table.

23.3 Using COUNT() in My Portfolio Database

I can apply COUNT() to my actual portfolio contact_messages table.

SQL — Total Contact Messages 
SELECT COUNT(*) AS total_messages
FROM contact_messages;

Here, AS total_messages gives the calculated result a meaningful column name.

I can also count only approved messages.

SQL — Count Approved Messages 
SELECT COUNT(*) AS approved_messages
FROM contact_messages
WHERE is_approved = 2;

The WHERE condition filters the records first. COUNT(*) then counts the rows that satisfy that condition.

23.4 Understanding SUM()

SUM() calculates the total of numeric values stored in a selected column.

For example, suppose I have a students table containing marks. If I want to calculate the total marks of all students, I can use SUM().

SQL — SUM Syntax 
SELECT SUM(column_name)
FROM table_name;
SQL — Calculate Total Marks 
SELECT SUM(marks) AS total_marks
FROM students;

If the marks are 80, 75, 90, 85 and 70, the result will be 400.

SUM() ignores NULL values. If there are no non-NULL values to add, it returns NULL.

23.5 Using SUM() with WHERE

I can also calculate the total marks of students belonging to a particular course.

SQL — Total Marks of BCA Students 
SELECT SUM(marks) AS bca_total_marks
FROM students
WHERE course = 'BCA';

First, MySQL selects the records where the course is BCA. Then SUM() calculates the total marks of those matching records.

23.6 Understanding AVG()

AVG() calculates the average value of a numeric column.

The average is calculated by adding the non-NULL numeric values and dividing their sum by the number of non-NULL values.

Average = Sum of Values / Number of Values
SQL — AVG Syntax 
SELECT AVG(column_name)
FROM table_name;
SQL — Average Student Marks 
SELECT AVG(marks) AS average_marks
FROM students;

Suppose the marks are 80, 75, 90, 85 and 70. Their total is 400 and there are five values. Therefore, the average is 80.

AVG() ignores NULL values. If there are no non-NULL numeric values, the result is NULL.

23.7 Using AVG() with WHERE

I can calculate the average marks of students who belong to a particular course.

SQL — Average Marks of BCA Students 
SELECT AVG(marks) AS average_bca_marks
FROM students
WHERE course = 'BCA';

This is useful when I want to compare the average performance of different student groups.

23.8 Understanding MIN()

MIN() returns the smallest value from a selected column.

For example, if I want to find the lowest marks obtained by students, I can use MIN().

SQL — MIN Syntax 
SELECT MIN(column_name)
FROM table_name;
SQL — Lowest Student Marks 
SELECT MIN(marks) AS lowest_marks
FROM students;

If the marks are 80, 75, 90, 85 and 70, MIN() returns 70.

MIN() ignores NULL values. It can also work with suitable non-numeric data types, such as dates and text values, according to their comparison rules.

23.9 Understanding MAX()

MAX() returns the largest value from a selected column.

If I want to find the highest marks obtained by students, I can use MAX().

SQL — MAX Syntax 
SELECT MAX(column_name)
FROM table_name;
SQL — Highest Student Marks 
SELECT MAX(marks) AS highest_marks
FROM students;

If the marks are 80, 75, 90, 85 and 70, MAX() returns 90.

23.10 Understanding MIN() and MAX() Together

I do not always need to execute separate queries to find the minimum and maximum values. I can use both functions in one SELECT statement.

SQL — Lowest and Highest Marks 
SELECT
    MIN(marks) AS lowest_marks,
    MAX(marks) AS highest_marks
FROM students;

This query returns both summary values in a single result row.

23.11 Using Multiple Aggregate Functions Together

One of the most useful things I learned is that I can use multiple aggregate functions in the same SELECT statement.

For example, I can calculate the total number of students, total marks, average marks, lowest marks and highest marks together.

SQL — Complete Student Summary

    COUNT(*) AS total_students,
    SUM(marks) AS total_marks,
    AVG(marks) AS average_marks,
    MIN(marks) AS lowest_marks,
    MAX(marks) AS highest_marks
FROM students;

Instead of running five separate queries, I can retrieve all five calculations in one query.

23.12 Aggregate Functions and NULL Values

While learning aggregate functions, I also needed to understand how they behave when a column contains NULL values.

Suppose my marks column contains these values:

SUM() and AVG() also ignore NULL values. MIN() and MAX() ignore NULL values when non-NULL values are available.

23.13 Aggregate Functions with DISTINCT

DISTINCT can also be used inside aggregate functions when I want to calculate using unique values only.

For example, imagine a table contains repeated marks. I may want to calculate the sum of unique marks rather than adding every repeated value.

FROM students;

Similarly, I can calculate the average of distinct marks.

SQL — AVG with DISTINCT 
SELECT AVG(DISTINCT marks)
FROM students;

These queries ignore repeated non-NULL values before performing their calculations.

I have already learned that AS can be used to provide a temporary name to a column. The same concept makes aggregate results easier to understand.

    MAX(marks) AS top_marks
FROM students;

The aliases total_records, class_average and top_marks are displayed as result column names. They do not rename the actual database columns.

23.16 Aggregate Functions and Empty Tables

Another useful detail is understanding what happens when a query does not find any matching records.

  • MIN(marks) returns NULL.

24. UPDATE and DELETE — Changing and Removing Database Records

In the previous chapters, I learned how to insert records into MySQL tables and retrieve them using SELECT. I also explored aggregate functions to calculate totals, averages, minimums and maximums.

But database management does not stop after inserting and reading records. Real applications continuously receive new information, and existing information sometimes needs correction or removal.

For example, when a visitor submits a contact form on my portfolio, their message is stored in the database. Later, I may need to correct a record, change its approval status, or remove an unwanted entry.

SQL provides two important commands for these operations: UPDATE and DELETE.

24.1 What Is UPDATE?

UPDATE is an SQL command used to modify existing records in a database table.

It allows me to change the values stored in one or more columns without deleting the entire record and inserting it again.

For example, suppose a student's marks were entered incorrectly. Instead of removing the student record, I can use UPDATE to correct the marks.

SQL — UPDATE Syntax 
UPDATE table_name
SET column_name = new_value
WHERE condition;

Let's understand the important parts:

  • UPDATE: Specifies the table whose records I want to modify.
  • SET: Specifies the column and its new value.
  • WHERE: Identifies which records should be updated.

24.2 Updating a Single Record

Imagine my students table contains the following record:

Existing Student Record

student_id student_name marks
101 Pooja 75

Now suppose I want to change Pooja's marks from 75 to 90.

SQL — Updating Student Marks 
UPDATE students
SET marks = 90
WHERE student_id = 101;

After executing the query, the record will contain 90 instead of 75.

Updated Student Record

student_id student_name marks
101 Pooja 90

24.3 Why Is WHERE Important in UPDATE?

While learning UPDATE, I realised that WHERE is extremely important because it controls which records will be modified.

Consider this query:

SQL — UPDATE Without WHERE 
UPDATE students
SET marks = 90;

This query updates the marks column for every row in the students table. It does not update only one student.

Therefore, whenever I want to update a particular record, I must carefully write the WHERE condition.

Important Difference

With WHERE: Only matching records are updated.

Without WHERE: All rows in the table are updated.

24.4 Updating Multiple Columns

UPDATE is not limited to changing only one column. I can modify multiple columns of the same matching record in a single query.

Suppose I want to update both the student's name and marks.

SQL — Updating Multiple Columns 
UPDATE students
SET
    student_name = 'Pooja Vartia',
    marks = 95
WHERE student_id = 101;

Here, both columns are updated for the student whose student_id is 101.

24.5 Updating Multiple Records Using Conditions

Sometimes I may want to update more than one record. In that situation, I can use a condition that matches multiple rows.

For example, suppose I want to add five bonus marks to all students belonging to BCA.

SQL — Updating a Group of Students 
UPDATE students
SET marks = marks + 5
WHERE course = 'BCA';

MySQL updates every matching BCA student record by adding five to the existing marks.

This also demonstrates that I can use arithmetic expressions inside the SET clause.

24.6 Updating Records with Multiple Conditions

I can also combine conditions using AND and OR to identify exactly which records need changes.

SQL — UPDATE with AND 
UPDATE students
SET marks = 100
WHERE course = 'BCA'
AND student_id = 101;

This query updates the marks only when both conditions are true.

I can also use IN when I need to update records belonging to multiple selected categories.

SQL — UPDATE with IN 
UPDATE students
SET course = 'Computer Applications'
WHERE student_id IN (101, 102, 103);

24.7 Updating a NULL Value

If a column currently contains NULL, I can replace that missing value using UPDATE.

For example, suppose a student's phone number was not available when the record was created. Later, when I receive the correct number, I can update the record.

SQL — Updating a NULL Value 
UPDATE students
SET phone = '9876543210'
WHERE student_id = 101
AND phone IS NULL;

I used IS NULL because NULL represents a missing or unknown value. It should not be compared using the ordinary equals operator.

24.8 Updating Data in My Portfolio Database

Now I wanted to connect UPDATE with my actual portfolio project.

My contact_messages table stores visitor messages. I also added an is_approved column to control which messages should appear publicly in my portfolio feedback section.

If I want to approve a particular message, I can update its approval status.

SQL — Approving a Visitor Message

WHERE id = 2;

SQL — Changing Approval Status

WHERE id = 2;

This example assumes that my application uses 0 for pending and 2 for approved. The actual meaning of each status depends on the rules I define in my application.

SQL — Checking the Updated Record

FROM contact_messages
WHERE id = 2;

This helps me confirm the current values stored in the selected record.

24.10 What Is DELETE?

UPDATE changes existing information, but sometimes I need to remove an entire record.

DELETE is an SQL command used to remove rows from a database table.

For example, if a student record was created by mistake and should no longer exist, I can delete that particular record.

SQL — DELETE Syntax

WHERE condition;

DELETE removes complete rows. It does not remove only one selected column from a record.

24.11 Deleting a Single Record

Suppose my students table contains a record with student_id 105, and I want to remove it.

SQL — Delete One Student 
DELETE FROM students
WHERE student_id = 105;

This query deletes the row whose student_id is 105.

Other student records remain unchanged.

24.12 Why Is WHERE Important in DELETE?

Just like UPDATE, DELETE also needs special attention when using WHERE.

Consider this query:

SQL — DELETE Without WHERE 
DELETE FROM students;

This query deletes all rows from the students table. The table itself remains available, but its records are removed.

This is why I should always check my DELETE condition before executing a query.

Important Difference

DELETE with WHERE: Removes only matching records.

DELETE without WHERE: Removes every row from the table.

24.13 Deleting Multiple Records with Conditions

I can delete more than one record by writing a condition that matches multiple rows.

For example, I may want to remove all records belonging to a particular course.

Every row where the course value is BCA will be deleted.

I can also combine multiple conditions.

WHERE student_id IN (101, 102, 103);

This query removes the records whose IDs match any of the listed values.

24.15 Deleting Records with NULL Values

I can also use IS NULL to identify records where a particular column has no stored value.

WHERE phone IS NULL;

This removes every student record where the phone column contains NULL. I should use such a query only when removing those complete records is actually intended.

25. COMMIT and ROLLBACK — Saving and Reversing Database Changes

In the previous chapter, I learned how to modify existing records using UPDATE and remove records using DELETE. These commands helped me understand how information can be maintained inside a database.

But while learning database management, I realised that changing data is not always a simple one-step operation. Sometimes an application needs to perform multiple related operations together.

Imagine a banking application where money is transferred from one account to another. The application needs to subtract money from one account and add the same amount to another.

What if money is deducted from the first account but the second account is not credited because an error occurs?

This is where database transactions become useful. They help manage a group of related database operations as one logical unit of work.

25.1 What Is a Database Transaction?

A database transaction is a sequence of database operations treated as one logical unit of work. The goal is to ensure that related changes are completed together or, when supported, rolled back together.

For example, a money transfer may involve:

  • Checking the sender's account balance.
  • Subtracting money from the sender's account.
  • Adding money to the receiver's account.
  • Confirming that both operations succeeded.

Instead of treating these operations as unrelated changes, the application can manage them inside one transaction.

25.2 Understanding the ACID Properties

While learning transactions, I also came across an important database concept called ACID. These four properties describe the reliability principles of database transactions.

  • A — Atomicity: A transaction is treated as one complete unit. Its supported operations succeed together, or the transaction is rolled back.
  • C — Consistency: A transaction should take the database from one valid state to another while respecting defined rules and constraints.
  • I — Isolation: Concurrent transactions should not interfere with each other in ways that violate the configured isolation guarantees.
  • D — Durability: Once a transaction is successfully committed, its changes are intended to survive failures, according to the database's durability configuration.

These properties help make database operations more dependable, especially when multiple users and applications access the same data.

25.3 What Is COMMIT?

COMMIT is a transaction control command used to permanently save the changes made within the current transaction.

When I execute COMMIT, the current transaction is completed and its changes become committed.

SQL — COMMIT Syntax 
COMMIT;

For example, suppose I want to insert a new student record and confirm that it should be saved.

SQL — Insert and Commit 
START TRANSACTION;

INSERT INTO students
    (student_id, student_name, marks)
VALUES
    (201, 'Pooja', 95);

COMMIT;

Here, START TRANSACTION begins a transaction. INSERT adds the student record, and COMMIT completes the transaction by saving its changes.

25.4 What Is ROLLBACK?

ROLLBACK is used to cancel the changes made within the current transaction that have not yet been committed.

It returns the transactional data changes to the state they had at the beginning of the transaction or at the relevant savepoint.

SQL — ROLLBACK Syntax 
ROLLBACK;

Suppose I accidentally insert an incorrect student record. Before committing the transaction, I can use ROLLBACK to cancel that insertion.

SQL — Insert and Roll Back 
START TRANSACTION;

INSERT INTO students
    (student_id, student_name, marks)
VALUES
    (202, 'Wrong Name', 50);

ROLLBACK;

The insertion is rolled back if the table uses a transactional storage engine such as InnoDB and no implicit commit has ended the transaction.

25.5 Understanding START TRANSACTION

Before using COMMIT and ROLLBACK, I need to understand how a transaction begins.

In MySQL, I can start a transaction using START TRANSACTION.

SQL — Starting a Transaction 
START TRANSACTION;

-- Write transactional SQL statements here

COMMIT;

MySQL also supports BEGIN and BEGIN WORK as alternatives for starting a transaction.

SQL — Alternative Transaction Syntax 
BEGIN;

-- Transaction statements

COMMIT;

START TRANSACTION is especially clear when I am learning SQL because it directly explains what I am doing.

25.6 Understanding a Transaction Step by Step

To understand the complete process, I created a simple example with a students table.

Suppose I want to update a student's marks and then save the change only after checking that the operation is correct.

SQL — Transaction with UPDATE 
-- Step 1: Begin transaction
START TRANSACTION;

-- Step 2: Update the student's marks
UPDATE students
SET marks = 95
WHERE student_id = 201;

-- Step 3: Check the updated record
SELECT *
FROM students
WHERE student_id = 201;

-- Step 4: Save the transaction
COMMIT;

In this example, the update is part of the transaction. After verifying the result, I commit the change.

If I discover that the update was incorrect before committing, I can use ROLLBACK instead.

25.7 Practical Example — Banking Money Transfer

The banking example is one of the easiest ways to understand why transactions are important.

Imagine two accounts:

Before Money Transfer

Account Balance
Account A ₹10,000
Account B ₹5,000

Now suppose Account A wants to transfer ₹2,000 to Account B.

The expected result is:

After Successful Transfer

Account Balance
Account A ₹8,000
Account B ₹7,000

I can represent this transfer using a transaction.

SQL — Money Transfer Transaction 
START TRANSACTION;

-- Deduct money from Account A
UPDATE accounts
SET balance = balance - 2000
WHERE account_id = 1
AND balance >= 2000;

-- Add money to Account B
UPDATE accounts
SET balance = balance + 2000
WHERE account_id = 2;

COMMIT;

This is a simplified illustration of a transfer. A real banking application must also verify that both accounts exist, check the affected row counts, validate the transaction, and handle errors. It should COMMIT only when all required operations have succeeded; otherwise, it should ROLLBACK.

This example also assumes that both account rows are stored in a transactional table such as InnoDB.

25.8 What Happens When an Error Occurs?

Suppose the money is deducted from Account A, but the second UPDATE fails.

If the application detects the failure and executes ROLLBACK before the transaction is committed, the first update can also be undone.

SQL — Transaction with Rollback 
START TRANSACTION;

UPDATE accounts
SET balance = balance - 2000
WHERE account_id = 1;

-- Suppose a problem occurs here

ROLLBACK;

ROLLBACK cancels the uncommitted transactional changes. It is important that the application handles errors and does not accidentally execute COMMIT after a failed operation.

25.9 Understanding SAVEPOINT

While exploring transactions, I also learned about SAVEPOINT.

SAVEPOINT creates a named point inside a transaction. It allows me to roll back only part of the transaction instead of cancelling every operation performed since the transaction began.

SQL — SAVEPOINT Syntax 
SAVEPOINT savepoint_name;

For example:

SQL — Creating a Savepoint 
START TRANSACTION;

UPDATE students
SET marks = 90
WHERE student_id = 201;

SAVEPOINT after_first_update;

UPDATE students
SET marks = 85
WHERE student_id = 202;

ROLLBACK TO SAVEPOINT after_first_update;

COMMIT;

Let's understand what happens:

  • The transaction begins.
  • The first student's marks are updated.
  • A savepoint is created.
  • The second student's marks are updated.
  • ROLLBACK TO SAVEPOINT reverses the second update.
  • COMMIT saves the remaining transaction changes.

Therefore, the first update remains committed, while the second update is rolled back.

25.10 Understanding RELEASE SAVEPOINT

RELEASE SAVEPOINT removes a named savepoint from the current transaction.

SQL — Releasing a Savepoint 
START TRANSACTION;

UPDATE students
SET marks = 90
WHERE student_id = 201;

SAVEPOINT marks_updated;

-- More transactional operations

RELEASE SAVEPOINT marks_updated;

COMMIT;

Releasing a savepoint does not commit the transaction. It only removes that savepoint. The transaction can still be rolled back or committed.

25.11 Understanding AUTOCOMMIT in MySQL

Another important concept I discovered is AUTOCOMMIT.

MySQL normally uses autocommit mode, which means that each successful statement is automatically committed when it is executed outside an explicit transaction.

I can check the current setting using:

SQL — Checking AUTOCOMMIT 
SELECT @@autocommit;

A result of 1 means autocommit is enabled, while 0 means it is disabled for the current session.

I can change the session setting using:

SQL — Disabling AUTOCOMMIT 
SET autocommit = 0;

And I can enable it again using:

SQL — Enabling AUTOCOMMIT 
SET autocommit = 1;

For learning purposes, I prefer using explicit START TRANSACTION, COMMIT and ROLLBACK because they make the transaction boundaries easier to understand.

25.12 Which Storage Engine Supports Transactions?

While learning MySQL transactions, I discovered that transaction support also depends on the storage engine used by a table.

MySQL supports different storage engines. One commonly used engine is InnoDB.

InnoDB supports transactions, COMMIT, ROLLBACK, foreign keys, and other important database features.

MyISAM is another MySQL storage engine, but it does not provide the same transactional support as InnoDB.

I can check the storage engine of a table using:

SQL — Checking Table Storage Engine 
SHOW TABLE STATUS
WHERE Name = 'contact_messages';

I can also inspect the table definition:

SQL — Checking Table Definition

If the table uses InnoDB, I can use its transaction features for supported operations.

25.13 Important Note About DDL and Transactions

I also needed to understand that not every SQL command behaves like a normal transactional INSERT, UPDATE or DELETE statement.

In MySQL, many DDL statements, such as CREATE, ALTER, DROP and TRUNCATE, cause implicit commits. This means they can end the current transaction instead of behaving like ordinary transactional data changes.

SQL — Example of DDL and Transactions 
START TRANSACTION;

UPDATE students
SET marks = 90
WHERE student_id = 201;

CREATE TABLE temporary_table (
    id INT PRIMARY KEY
);

ROLLBACK;

I should not assume that ROLLBACK will undo everything in this example. CREATE TABLE causes an implicit commit in MySQL, so the earlier UPDATE may already have been committed.

This is why I should avoid mixing DDL operations with transactional data changes when I expect everything to be reversible as one unit.

Completes the transaction. Completes the transaction when used without a savepoint.

26. Primary Keys and Foreign Keys — Establishing Relationships Between Tables

In the previous chapters, I learned how to create databases and tables, insert records, retrieve information, update existing values, and manage transactions using COMMIT and ROLLBACK.

But while understanding database design, I realised that a real application rarely stores every piece of information inside one large table.

For example, imagine an online shopping application. It may have separate tables for customers, products, orders, and payments. These tables need a way to identify and connect related records.

If I store everything in one table, the same customer information may be repeated many times. This can create duplication and make data management difficult.

To organise related information properly, relational databases use keys.

26.1 What Is a Key in a Database?

A key is a column or combination of columns used to identify records, establish relationships, or enforce uniqueness in a database table.

Keys help me organise information and connect related tables without unnecessarily repeating the same data.

Two important keys I need to understand first are:

  • Primary Key: Uniquely identifies each record in a table.
  • Foreign Key: Establishes a relationship with a key in another table.

26.2 What Is a Primary Key?

A Primary Key is a column or combination of columns that uniquely identifies every record in a table.

Every table can have only one PRIMARY KEY constraint, but that key can contain multiple columns. This is called a composite primary key.

A primary key cannot contain NULL values, and its values must be unique.

For example, imagine I have a students table:

Students Table

student_id student_name course
101 Pooja BCA
102 Priya BCA
103 Aman BBA
104 Simran BCA

Here, student_id uniquely identifies every student. Even if two students have the same name, their IDs can remain different.

Therefore, student_id is a suitable primary key for this table.

26.3 Why Do We Need a Primary Key?

Without a unique identifier, it can become difficult to identify a particular record, especially when different records contain similar information.

Consider two students with the same name:

Duplicate Names Without a Unique Identifier

student_name course
Rahul BCA
Rahul BBA

If I search only by name, I may retrieve more than one record. But when I introduce a unique student_id, I can identify the exact student.

A primary key therefore helps with:

  • Uniquely identifying every record.
  • Preventing duplicate key values.
  • Preventing NULL values in the key.
  • Updating or deleting a specific record.
  • Establishing relationships with other tables.

26.4 Creating a Primary Key While Creating a Table

When I create a table, I can define its primary key directly inside the CREATE TABLE statement.

SQL — Primary Key Syntax 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(100),
    course VARCHAR(50)
);

Here, student_id is the primary key. MySQL will not allow duplicate or NULL values in this column.

26.5 Using AUTO_INCREMENT with a Primary Key

While creating tables, I often use AUTO_INCREMENT with an integer primary key.

AUTO_INCREMENT allows MySQL to generate successive numeric values automatically when new records are inserted without providing an explicit ID.

SQL — Primary Key with AUTO_INCREMENT 
CREATE TABLE students (
    student_id INT AUTO_INCREMENT PRIMARY KEY,
    student_name VARCHAR(100) NOT NULL,
    course VARCHAR(50)
);

Now I can insert student information without manually providing student_id.

SQL — Inserting Records 
INSERT INTO students (student_name, course)
VALUES
('Pooja', 'BCA'),
('Priya', 'BCA'),
('Aman', 'BBA');

MySQL generates the AUTO_INCREMENT values automatically, subject to the table's existing sequence and configuration.

26.6 Adding a Primary Key to an Existing Table

Sometimes I may create a table first and decide to add a primary key later. In that situation, I can use ALTER TABLE.

SQL — Adding a Primary Key 
ALTER TABLE students
ADD PRIMARY KEY (student_id);

Before adding a primary key to an existing table, I must make sure that the selected column contains no duplicate or NULL values.

Otherwise, MySQL will reject the operation.

26.7 What Is a Composite Primary Key?

A primary key does not always need to be a single column. Sometimes two or more columns together uniquely identify a record.

This type of key is called a Composite Primary Key.

Imagine an enrollment table that stores which students have registered for which courses. A student may register for multiple courses, and a course may contain multiple students.

SQL — Composite Primary Key 
CREATE TABLE enrollments (
    student_id INT,
    course_id INT,
    enrollment_date DATE,

    PRIMARY KEY (student_id, course_id)
);

Here, the combination of student_id and course_id must be unique. The same student cannot have a duplicate enrollment for the same course under this key design.

26.8 What Is a Foreign Key?

Now that I understand how a primary key identifies a record, I can move to the second important concept: Foreign Key.

A Foreign Key is a column or group of columns in one table that references a candidate key in another table, commonly its primary key.

It helps establish a relationship between two tables and maintains referential integrity.

Let's understand this with an example.

Parent Table — Students

student_id student_name
101 Pooja
102 Priya
103 Aman

Child Table — Enrollments

enrollment_id student_id course
1 101 HTML
2 101 MySQL
3 102 CSS

Here, student_id is the primary key in the students table and a foreign key in the enrollments table.

This relationship allows multiple enrollment records to refer to the same student.

26.9 Understanding Parent and Child Tables

In a foreign key relationship, I commonly describe the referenced table as the parent table and the table containing the foreign key as the child table.

  • Parent Table: Contains the referenced candidate key, usually a primary key.
  • Child Table: Contains the foreign key that refers to the parent table.

In my example:

  • students is the parent table.
  • enrollments is the child table.
  • student_id connects both tables.

26.10 Creating a Foreign Key While Creating a Table

I can define a foreign key inside the CREATE TABLE statement.

SQL — Creating a Parent Table 
CREATE TABLE students (
    student_id INT AUTO_INCREMENT PRIMARY KEY,
    student_name VARCHAR(100) NOT NULL
) ENGINE=InnoDB;

Now I can create the child table.

SQL — Creating a Child Table with Foreign Key 
CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NOT NULL,
    course VARCHAR(100),

    CONSTRAINT fk_enrollment_student
    FOREIGN KEY (student_id)
    REFERENCES students(student_id)

) ENGINE=InnoDB;

The constraint name fk_enrollment_student is a name I have chosen for this foreign key. It helps me identify the relationship when inspecting or modifying the table.

These records are valid because the referenced student IDs already exist in the students table.

26.12 What Happens if a Foreign Key Value Does Not Exist?

One of the most important things I learned is that a foreign key prevents a child record from referencing a non-existing parent record.

For example, suppose I try to insert an enrollment for student_id 999, but no student with that ID exists.

SQL — Invalid Foreign Key Example 
INSERT INTO enrollments (student_id, course)
VALUES (999, 'PHP');

MySQL rejects this insert because student_id 999 does not exist in the referenced students table.

This helps prevent orphan records and maintains consistency between related tables.

26.13 Understanding Referential Integrity

Referential integrity is the principle that relationships between tables should remain valid.

For example, if an enrollment refers to student ID 101, the referenced student should exist according to the foreign key rules.

Foreign keys help enforce this rule automatically.

They protect the database from situations such as:

  • Inserting a child record with a non-existing parent ID.
  • Deleting a parent record while dependent child records still exist, unless an allowed action is configured.
  • Changing a referenced key in a way that violates the relationship.

26.14 Understanding ON DELETE CASCADE

Sometimes I may want related child records to be deleted automatically when their parent record is deleted.

For this purpose, MySQL supports ON DELETE CASCADE.

Suppose I delete a student, and I also want to remove that student's enrollment records.

SQL — Foreign Key with ON DELETE CASCADE 
CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NOT NULL,
    course VARCHAR(100),

    CONSTRAINT fk_student_cascade
    FOREIGN KEY (student_id)
    REFERENCES students(student_id)
    ON DELETE CASCADE

) ENGINE=InnoDB;

Now, when a referenced student is deleted, MySQL automatically deletes the matching enrollment records.

I should use CASCADE carefully because one parent deletion can remove multiple related child records.

26.15 Understanding ON UPDATE CASCADE

Another useful option is ON UPDATE CASCADE.

It means that if a referenced parent key value is updated, the matching foreign key values in the child table are updated automatically.

SQL — ON UPDATE CASCADE 
CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NOT NULL,
    course VARCHAR(100),

    CONSTRAINT fk_student_update
    FOREIGN KEY (student_id)
    REFERENCES students(student_id)
    ON UPDATE CASCADE

) ENGINE=InnoDB;

Although this feature is available, primary key values are generally designed to remain stable. Therefore, I should not update them without a clear reason.

26.16 Understanding ON DELETE SET NULL

Another foreign key action is ON DELETE SET NULL.

When the referenced parent record is deleted, the related foreign key value in the child table is set to NULL instead of deleting the child record.

SQL — ON DELETE SET NULL 
CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NULL,
    course VARCHAR(100),

    CONSTRAINT fk_student_set_null
    FOREIGN KEY (student_id)
    REFERENCES students(student_id)
    ON DELETE SET NULL

) ENGINE=InnoDB;

The student_id column must allow NULL values for this action to work.

26.17 Understanding ON DELETE RESTRICT and NO ACTION

Sometimes I do not want a parent record to be deleted while child records still refer to it.

For this purpose, I can use RESTRICT.

SQL — ON DELETE RESTRICT 
CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NOT NULL,
    course VARCHAR(100),

    CONSTRAINT fk_student_restrict
    FOREIGN KEY (student_id)
    REFERENCES students(student_id)
    ON DELETE RESTRICT

) ENGINE=InnoDB;

If matching child records exist, MySQL prevents deletion of the referenced parent.

NO ACTION is also supported. In MySQL's InnoDB engine, NO ACTION behaves like RESTRICT for foreign key checking.

26.18 Adding a Foreign Key to an Existing Table

Just like a primary key, I can also add a foreign key after a table has already been created.

SQL — Adding a Foreign Key with ALTER TABLE 
ALTER TABLE enrollments
ADD CONSTRAINT fk_enrollment_student
FOREIGN KEY (student_id)
REFERENCES students(student_id);

Before adding the constraint, I must ensure that existing child records do not contain invalid references.

26.19 Removing a Foreign Key Constraint

If I need to remove a foreign key relationship, I can use ALTER TABLE with DROP FOREIGN KEY.

SQL — Dropping a Foreign Key 
ALTER TABLE enrollments
DROP FOREIGN KEY fk_enrollment_student;

This removes the foreign key constraint, but it does not delete the student_id column or its stored values.

26.21 Important Rules for Foreign Keys in MySQL

While creating foreign key relationships, I need to remember some important rules.

  • The referenced table must exist before I create the foreign key relationship.
  • The referenced columns must be indexed appropriately. A primary key is a common choice.
  • The child and referenced columns must have compatible data types.
  • For integer columns, size and signedness should match.
  • Both tables should use a storage engine that supports foreign keys, such as InnoDB.
  • A foreign key value can be NULL if the column allows NULL and the relationship is optional.
  • Existing child records must satisfy the foreign key rule before the constraint can be added.

27. Understanding SQL Joins — Retrieving Data from Multiple Tables

In the previous chapter, I learned how primary keys and foreign keys establish relationships between different tables in a relational database.

But after creating those relationships, another question came to my mind: How can I retrieve information from two or more related tables together?

For example, imagine I have a students table containing student details and an enrollments table containing their course registrations. If I want to display a student's name along with the courses they have selected, I need information from both tables.

This is where SQL JOIN becomes useful.

27.1 What Is a JOIN in SQL?

A JOIN is an SQL operation that combines columns from two or more tables based on a related column or a specified join condition.

Instead of retrieving information separately from every table, I can use a JOIN to retrieve related information in one result set.

For example:

  • The students table contains student names.
  • The enrollments table contains course information.
  • Both tables share student_id.
  • A JOIN can combine these records using student_id.

27.2 Understanding the Tables Before Joining

Before writing JOIN queries, I first created two example tables to understand how their records are related.

Table 1 — students

student_id student_name
1 Pooja
2 Priya
3 Aman
4 Simran

Table 2 — enrollments

enrollment_id student_id course
101 1 HTML
102 1 MySQL
103 2 CSS
104 3 JavaScript
105 5 PHP

Notice something interesting: student_id 1 appears twice in the enrollments table because Pooja has registered for two courses.

Also, student_id 4 has no enrollment, while student_id 5 appears in enrollments but does not exist in the students table.

The last situation would not be allowed if these tables had an enforced foreign key relationship. I have intentionally included it here to understand how different JOIN types behave with unmatched records.

27.3 General Syntax of SQL JOIN

The basic structure of a JOIN query is:

SQL — General JOIN Syntax 
SELECT columns
FROM table1
JOIN table2
ON table1.common_column = table2.common_column;

Here:

  • SELECT: Specifies the columns I want to retrieve.
  • FROM: Specifies the first table.
  • JOIN: Specifies the second table.
  • ON: Defines the condition used to match records.

27.4 Understanding Different Types of SQL Joins

SQL supports different JOIN types. Each type determines which matching or non-matching records should appear in the result.

  • INNER JOIN
  • LEFT JOIN (LEFT OUTER JOIN)
  • RIGHT JOIN (RIGHT OUTER JOIN)
  • CROSS JOIN
  • SELF JOIN

I will understand each one with the same example tables so that the differences become easier to recognise.

27.5 INNER JOIN — Only Matching Records

INNER JOIN returns only those records that satisfy the specified join condition in both tables.

If a student has a matching enrollment, the record appears in the result. If there is no matching record, it is excluded.

INNER JOIN — Matching Records

Only students with matching enrollment records are included.

student_id student_name course
1 Pooja HTML
1 Pooja MySQL
2 Priya CSS
3 Aman JavaScript
SQL — INNER JOIN 
SELECT
    students.student_id,
    students.student_name,
    enrollments.course
FROM students
INNER JOIN enrollments
ON students.student_id = enrollments.student_id;

The result includes Pooja, Priya, and Aman because their student IDs match in both tables. Simran is excluded because she has no enrollment.

The enrollment for student_id 5 is also excluded because no matching student exists.

INNER JOIN is commonly used when I only want records that have a valid match in both tables.

27.6 INNER JOIN vs JOIN

While reading SQL queries, I may notice that some developers write JOIN without specifying INNER.

In MySQL, JOIN by itself means INNER JOIN unless another join type is specified.

SQL — Both Queries Have the Same Meaning 
SELECT *
FROM students
INNER JOIN enrollments
ON students.student_id = enrollments.student_id;

-- Equivalent shorthand

SELECT *
FROM students
JOIN enrollments
ON students.student_id = enrollments.student_id;

27.7 LEFT JOIN — All Records from the Left Table

LEFT JOIN returns all records from the left table and the matching records from the right table.

If a record from the left table has no match in the right table, the right table's columns contain NULL in the result.

In my example, students is the left table because it appears first after FROM.

LEFT JOIN — All Students

student_id student_name course
1 Pooja HTML
1 Pooja MySQL
2 Priya CSS
3 Aman JavaScript
4 Simran NULL
SQL — LEFT JOIN 
SELECT
    students.student_id,
    students.student_name,
    enrollments.course
FROM students
LEFT JOIN enrollments
ON students.student_id = enrollments.student_id;

Notice that Simran appears even though she has no course registration. Her course value is NULL because there is no matching enrollment.

This JOIN is especially useful when I want to display all users, customers, or students, including those who have not created any related records yet.

27.8 Finding Records Without a Match Using LEFT JOIN

One practical use of LEFT JOIN is finding records that do not have a matching record in another table.

For example, if I want to find students who have not registered for any course, I can combine LEFT JOIN with IS NULL.

SQL — Students Without Enrollments 
SELECT
    students.student_id,
    students.student_name
FROM students
LEFT JOIN enrollments
ON students.student_id = enrollments.student_id
WHERE enrollments.student_id IS NULL;

This query returns Simran because she has no matching enrollment.

This pattern is sometimes called an anti-join: it helps identify records from one table that have no match in another.

27.9 RIGHT JOIN — All Records from the Right Table

RIGHT JOIN works similarly to LEFT JOIN, but it preserves all records from the right-hand table.

In this example, enrollments is the right table. Therefore, every enrollment record appears, even when there is no matching student.

RIGHT JOIN — All Enrollments

student_id student_name course
1 Pooja HTML
1 Pooja MySQL
2 Priya CSS
3 Aman JavaScript
5 NULL PHP
SQL — RIGHT JOIN 
SELECT
    students.student_id,
    students.student_name,
    enrollments.course
FROM students
RIGHT JOIN enrollments
ON students.student_id = enrollments.student_id;

The enrollment for student_id 5 appears, but the student_name is NULL because the matching student does not exist.

This example demonstrates RIGHT JOIN behaviour. In a database with an enforced foreign key, such an unmatched child record would normally be prevented.

27.10 LEFT JOIN vs RIGHT JOIN

The main difference is which table's unmatched records are preserved.

  • LEFT JOIN: Keeps every row from the left table.
  • RIGHT JOIN: Keeps every row from the right table.
  • INNER JOIN: Keeps only matching rows.

I can often rewrite a RIGHT JOIN as a LEFT JOIN by swapping the order of the tables. Many developers prefer LEFT JOIN because its reading order can feel more natural.

27.11 CROSS JOIN — Combining Every Row with Every Row

CROSS JOIN returns the Cartesian product of two tables.

This means every row from the first table is combined with every row from the second table.

For example, if one table contains 3 rows and another contains 2 rows, the result contains 3 × 2 = 6 combinations.

Example — Colors

color
Red
Blue
Green

Example — Sizes

size
Small
Large

A CROSS JOIN between these tables produces every possible color and size combination.

SQL — CROSS JOIN 
SELECT
    colors.color,
    sizes.size
FROM colors
CROSS JOIN sizes;

The result contains six combinations: Red-Small, Red-Large, Blue-Small, Blue-Large, Green-Small, and Green-Large.

CROSS JOIN is useful when generating all possible combinations, such as product variations or scheduling possibilities. However, it can produce a very large result when the tables contain many rows.

27.12 SELF JOIN — Joining a Table with Itself

A SELF JOIN is used when I need to compare or connect records within the same table.

For example, imagine an employees table where each employee may have a manager. The manager is also an employee, so both employee and manager information exists in the same table.

Employees Table

To display each employee's name along with their manager's name, I can use SELF JOIN.

SQL — SELF JOIN 
SELECT
    employee.employee_name AS employee,
    manager.employee_name AS manager
FROM employees AS employee
LEFT JOIN employees AS manager
ON employee.manager_id = manager.employee_id;

Here, I use aliases to refer to the same table in two different roles.

  • employee: Represents the employee record.
  • manager: Represents the manager record.
  • ON: Matches manager_id with employee_id.

27.13 Understanding Table Aliases in JOINs

When working with multiple tables, writing complete table names again and again can make a query lengthy.

To make queries shorter and easier to read, I can assign aliases to tables.

SQL — JOIN Using Table Aliases 
SELECT
    s.student_name,
    e.course
FROM students AS s
INNER JOIN enrollments AS e
ON s.student_id = e.student_id;

Here, s represents students and e represents enrollments.

AS is optional for table aliases in MySQL, but using it can make the query easier to understand.

27.14 Joining More Than Two Tables

In real applications, information may be distributed across several related tables. SQL allows me to join more than two tables in a single query.

Imagine an application containing:

  • students — stores student details.
  • enrollments — connects students with courses.
  • courses — stores course names and details.

If I want to display a student's name and the actual course name, I can join all three tables.

SQL — Joining Three Tables 
SELECT
    s.student_name,
    c.course_name
FROM students AS s
INNER JOIN enrollments AS e
ON s.student_id = e.student_id
INNER JOIN courses AS c
ON e.course_id = c.course_id;

The query first connects students with enrollments and then connects enrollments with courses.

Each JOIN needs its own relationship condition so that the database knows how the records are connected.

27.15 JOIN with WHERE — Filtering Combined Results

JOIN can also be combined with WHERE. This allows me to retrieve related records while applying additional conditions.

SQL — JOIN with WHERE 
SELECT
    s.student_name,
    e.course
FROM students AS s
INNER JOIN enrollments AS e
ON s.student_id = e.student_id
WHERE e.course = 'MySQL';

This query returns students who have registered for the MySQL course.

27.16 Difference Between ON and WHERE

While learning JOINs, I also needed to understand the difference between ON and WHERE.

  • ON: Defines how records from two tables should match.
  • WHERE: Filters the resulting records according to a condition.

One important detail is that ON and WHERE are not interchangeable in every situation, especially when working with LEFT JOIN and RIGHT JOIN.

For example, these queries can produce different results:

SQL — Condition Inside ON 
SELECT
    s.student_name,
    e.course
FROM students AS s
LEFT JOIN enrollments AS e
ON s.student_id = e.student_id
AND e.course = 'MySQL';

This keeps every student but attaches only matching MySQL enrollment records.

SQL — Condition Inside WHERE 
SELECT
    s.student_name,
    e.course
FROM students AS s
LEFT JOIN enrollments AS e
ON s.student_id = e.student_id
WHERE e.course = 'MySQL';

This returns only rows where the course is MySQL. Students without a matching enrollment are removed from the result.

This is why I should understand the placement of conditions when using outer joins.

27.17 Understanding JOIN vs UNION

JOIN and UNION may look similar because both can combine query results, but they perform different operations.

  • JOIN: Combines columns from related tables, placing information side by side.
  • UNION: Combines the rows returned by separate SELECT statements, placing one result below another.

I will explore UNION and UNION ALL in a separate chapter.

27.18 Common JOIN Mistakes I Should Avoid

  • Forgetting the ON condition and accidentally generating an unintended Cartesian product.
  • Joining columns that do not represent the same relationship.
  • Using ambiguous column names without table names or aliases.
  • Forgetting that one parent record may match multiple child records.
  • Using WHERE conditions that unintentionally remove NULL-extended rows from an outer JOIN.
  • Assuming result order is guaranteed without using ORDER BY.

28. GROUP BY and HAVING — Organising Records into Meaningful Groups

In the previous chapters, I learned how to retrieve records using SELECT, filter information using WHERE, calculate values using aggregate functions, and combine multiple tables using JOINs.

But while working with database records, I realised that sometimes retrieving individual rows is not enough. I may want to know how many students are enrolled in each course, how many messages each user has submitted, or how many bus schedules belong to each user.

Instead of checking every record separately, I need a way to organise similar records into groups and calculate information for each group.

This is where GROUP BY and HAVING become useful.

28.1 What Is GROUP BY in SQL?

GROUP BY is an SQL clause that groups rows having the same values in one or more columns. It is commonly used with aggregate functions such as COUNT(), SUM(), AVG(), MIN(), and MAX().

After grouping records, SQL can calculate a separate result for each group.

For example, imagine a students table where many students belong to different courses. If I want to count how many students are enrolled in each course, I can use GROUP BY.

SQL — GROUP BY Syntax

Here:

  • Aggregate Function: Calculates a value for each group.

28.10 What Is HAVING in SQL?

After learning GROUP BY, I needed a way to filter the grouped results.

For example, suppose I want to display only those courses that have more than two enrolled students.

WHERE filters individual rows before grouping, but HAVING filters groups after the grouping operation.

This is the purpose of HAVING.

SQL — Basic HAVING Syntax 
SELECT column_name, aggregate_function(column_name)
FROM table_name
GROUP BY column_name
HAVING condition;

28.11 GROUP BY with HAVING and COUNT()

Now I can return to my enrollment example. If I want to display only those courses having more than two students, I can write:

SQL — Courses with More Than Two Students

    course,
    COUNT(*) AS total_students
FROM enrollments
GROUP BY course
HAVING COUNT(*) > 2;

The result will contain only HTML because three students are enrolled in that course. CSS and JavaScript each have two students.

28.12 GROUP BY with HAVING and SUM()

HAVING can also filter groups according to their aggregate totals.

For example, I may want to display only those courses where the total collected fee is greater than 2500.

SQL — Filter Groups by Total Fees 
SELECT
    course,
    SUM(fees) AS total_fees
FROM enrollments
GROUP BY course
HAVING SUM(fees) > 2500;

This query returns HTML and JavaScript because their total fees are greater than 2500.

28.13 Difference Between WHERE and HAVING

This is one of the most important differences I learned while working with grouped data.

  • WHERE: Filters individual records before they are grouped.
  • HAVING: Filters groups after GROUP BY has been applied.

Understanding the Difference

WHERE example:

Find only enrollments where the course fee is greater than 1000.

HAVING example:

Find only those courses where the total fee collected is greater than 2500.

SQL — WHERE and HAVING Together 
SELECT
    course,
    COUNT(*) AS total_students,
    SUM(fees) AS total_fees
FROM enrollments
WHERE fees >= 1000
GROUP BY course
HAVING COUNT(*) >= 2;

Here, WHERE first removes records whose fees are below 1000. Then GROUP BY groups the remaining records by course. Finally, HAVING keeps only groups containing at least two records.

28.14 Can WHERE Use Aggregate Functions?

An aggregate function such as COUNT() or SUM() generally cannot be used directly in the WHERE clause of the same query.

This is because WHERE filters individual rows before the grouped aggregate result is calculated.

For example, this is not the correct way to filter grouped counts:

SQL — Incorrect Aggregate Filtering 
SELECT
    course,
    COUNT(*) AS total_students
FROM enrollments
WHERE COUNT(*) > 2
GROUP BY course;

Instead, I should use HAVING:

SQL — Correct Aggregate Filtering 
SELECT
    course,
    COUNT(*) AS total_students
FROM enrollments
GROUP BY course
HAVING COUNT(*) > 2;

    COUNT(*) AS total_students
FROM enrollments
GROUP BY course
ORDER BY total_students DESC;

ORDER BY sorts the final grouped results. DESC places the highest student count first.

    course,
    COUNT(*) AS total_students
FROM enrollments
GROUP BY course
ORDER BY total_students DESC
LIMIT 2;

This query displays the two courses with the highest student counts.

28.17 Understanding NULL Values with GROUP BY

GROUP BY also handles NULL values. If a grouped column contains NULL, all NULL values are placed into one group.

For example, if some students do not have a course assigned, their records can appear together in a NULL group.

SQL — Grouping NULL Values 
SELECT
    course,
    COUNT(*) AS total_students
FROM enrollments
GROUP BY course;

If course contains NULL values, the result includes a separate group for those records.

I can use COALESCE() to display a readable label instead of NULL:

SQL — Replacing NULL in Display 
SELECT

    COUNT(*) AS total_students
FROM enrollments
GROUP BY course;

28.18 Understanding SQL Query Execution Order

While writing queries, I noticed that SQL statements are written in one order, but the database logically processes their clauses in another order.

A simplified logical processing order for a SELECT query is:

  1. FROM and JOIN
  2. WHERE
  3. GROUP BY
  4. HAVING
  5. SELECT
  6. DISTINCT
  7. ORDER BY
  8. LIMIT

Understanding this order makes it easier to understand why WHERE cannot normally filter an aggregate calculated later by GROUP BY.

This is a logical explanation of query processing, not a guarantee of the exact physical execution plan chosen by MySQL.

28.19 GROUP BY and MySQL's ONLY_FULL_GROUP_BY Mode

While learning GROUP BY, I also discovered that MySQL can enforce a rule called ONLY_FULL_GROUP_BY.

When this SQL mode is enabled, I cannot select an ordinary column that is neither included in GROUP BY nor validly functionally dependent on the grouped columns.

For example, this query can produce an error under ONLY_FULL_GROUP_BY:

SQL — Invalid Grouped Selection 
SELECT
    course,
    student_name,
    COUNT(*)
FROM enrollments
GROUP BY course;

Why? Because each course may contain multiple student names. MySQL cannot choose one meaningful student_name for the entire group.

A correct version is:

SQL — Correct Grouped Selection 
SELECT
    course,
    COUNT(*) AS total_students
FROM enrollments
GROUP BY course;

If I need individual student names, I should retrieve them separately or use an appropriate aggregate or query design.

29. Subqueries in SQL — Writing a Query Inside Another Query

In the previous chapters, I learned how to retrieve records, filter information, combine tables using JOINs, and analyse grouped data using GROUP BY and HAVING.

But sometimes, while writing an SQL query, I may need information that is not directly available in the table I am currently querying. I may first need to calculate a value or retrieve a result and then use that result in another query.

For example, imagine I want to find students whose course fees are greater than the average fees of all students.

First, I need to calculate the average fees. Then I need to compare every student's fees with that calculated average.

Instead of calculating the average manually and writing it as a fixed value, I can place one SELECT statement inside another SELECT statement.

This is called a Subquery.

29.1 What Is a Subquery?

A subquery is a query written inside another SQL query. It is also called an inner query or nested query.

The query containing the subquery is called the outer query or main query.

  • Inner Query: The query written inside another query.
  • Outer Query: The main query that uses the inner query's result.

A subquery is generally written inside parentheses so that SQL can distinguish it from the outer query.

29.2 Basic Syntax of a Subquery

The general structure of a subquery looks like this:

SQL — Basic Subquery Syntax 
SELECT column_name
FROM table_name
WHERE column_name = (
    SELECT column_name
    FROM another_table
    WHERE condition
);

Here, the inner SELECT statement executes as part of the overall query. Its result is then used by the outer query.

29.3 Understanding the Example Table

Before practising subqueries, I will use a course_enrollments table containing student names, courses, and fees.

29.4 Simple Subquery Using a Fixed Condition

Suppose I want to find students whose fees are greater than the fees paid by Pooja.

I can solve this in two steps:

  1. Find Pooja's fees using an inner query.
  2. Find students whose fees are greater than that result using the outer query.
SQL — Fees Greater Than Pooja's Fees 
SELECT
    student_name,
    fees
FROM course_enrollments
WHERE fees > (
    SELECT fees
    FROM course_enrollments
    WHERE student_name = 'Pooja'
);

The inner query finds Pooja's fees, which are 1000.

The outer query then returns students whose fees are greater than 1000.

29.5 Understanding How a Subquery Works Step by Step

SELECT fees

This is how a subquery allows me to use the result of one query inside another.

29.6 Subquery with Comparison Operators

A subquery can be used with comparison operators such as:

  • = Equal to
  • != or <> Not equal to
  • > Greater than
  • < Less than
  • >= Greater than or equal to
  • <= Less than or equal to

For example, I can find students whose fees are equal to the highest fee:

SQL — Equal to a Subquery Result 
SELECT
    student_name,
    fees
FROM course_enrollments
WHERE fees = (
    SELECT MAX(fees)
    FROM course_enrollments
);

The inner query calculates the maximum fee, and the outer query finds the student or students having that fee.

29.7 Subquery with IN Operator

Sometimes an inner query returns multiple values instead of a single value. In such situations, I can use IN.

IN checks whether a value matches any value in the list or result returned by the subquery.

For example, imagine I want to find students who are enrolled in courses having more than one registration.

SQL — Subquery with IN 
SELECT
    student_name,
    course
FROM course_enrollments
WHERE course IN (
    SELECT course
    FROM course_enrollments
    GROUP BY course
    HAVING COUNT(*) > 1
);

The inner query first finds courses having more than one enrollment. The outer query then retrieves students enrolled in those courses.

29.8 Subquery with NOT IN

NOT IN is used when I want to exclude values returned by the inner query.

For example, imagine I have a courses table and want to find courses that do not appear in the enrollments table.

SQL — Subquery with NOT IN 
SELECT
    course_id,
    course_name
FROM courses
WHERE course_id NOT IN (
    SELECT course_id
    FROM enrollments
);

This query finds courses without matching enrollment records.

One important point: NOT IN can behave unexpectedly if the inner query returns NULL, because SQL uses three-valued logic. When checking for missing relationships, NOT EXISTS is often a safer choice.

29.9 Subquery with ANY Operator

ANY is used with a comparison operator. The condition becomes true if the comparison is true for at least one value returned by the subquery.

For example, I can find students whose fees are greater than at least one fee paid by students enrolled in CSS.

SQL — Subquery with ANY 
SELECT
    student_name,
    fees
FROM course_enrollments
WHERE fees > ANY (
    SELECT fees
    FROM course_enrollments
    WHERE course = 'CSS'
);

If the CSS fees are 1200 and 1800, a student qualifies when their fees are greater than at least one of those values.

In other words, the condition is true when the fee is greater than the smallest qualifying value in that non-empty result.

29.10 Subquery with ALL Operator

ALL is also used with comparison operators, but it checks whether the comparison is true for every value returned by the inner query.

For example, I can find students whose fees are greater than all fees paid by CSS students.

SQL — Subquery with ALL 
SELECT
    student_name,
    fees
FROM course_enrollments
WHERE fees > ALL (
    SELECT fees
    FROM course_enrollments
    WHERE course = 'CSS'
);

Here, a student's fees must be greater than every fee returned by the inner query.

29.11 Subquery with EXISTS

EXISTS is used to check whether a subquery returns at least one row.

It does not need to return a particular column value. It only checks whether a matching record exists.

For example, suppose I have students and enrollments tables. I want to find students who have at least one enrollment.

SQL — Subquery with EXISTS 
SELECT
    s.student_id,
    s.student_name
FROM students AS s
WHERE EXISTS (
    SELECT 1
    FROM enrollments AS e
    WHERE e.student_id = s.student_id
);

This is a correlated subquery because the inner query refers to s.student_id from the outer query.

The inner query checks each student for a matching enrollment. If at least one matching row exists, that student is included.

I will explore EXISTS and NOT EXISTS in more detail in the next chapter.

29.12 Subquery with NOT EXISTS

NOT EXISTS checks whether the inner query returns no matching rows.

Using the same tables, I can find students who have not registered for any course.

SQL — Subquery with NOT EXISTS 
SELECT
    s.student_id,
    s.student_name
FROM students AS s
WHERE NOT EXISTS (
    SELECT 1
    FROM enrollments AS e
    WHERE e.student_id = s.student_id
);

This query returns students for whom no matching enrollment record exists.

29.13 Subquery Inside the FROM Clause

A subquery can also be written inside the FROM clause.

In this situation, the inner query creates a temporary result set that the outer query can treat like a table.

In MySQL, a derived table in the FROM clause must have an alias.

SQL — Subquery Inside FROM 
SELECT
    course_summary.course,
    course_summary.total_students
FROM (
    SELECT
        course,
        COUNT(*) AS total_students
    FROM course_enrollments
    GROUP BY course
) AS course_summary;

Here, the inner query groups enrollment records by course and calculates the number of students.

The outer query retrieves the result from the derived table named course_summary.

29.14 Subquery Inside the SELECT Clause

I can also use a subquery inside the SELECT list to calculate an additional value for each row.

For example, I want to display every student's fees along with the average fees of all students.

SQL — Subquery Inside SELECT 
SELECT
    student_name,
    fees,
    (
        SELECT AVG(fees)
        FROM course_enrollments
    ) AS average_fees
FROM course_enrollments;

The average fee is calculated by the inner query and displayed alongside every student's record.

This is a scalar subquery because it returns a single value.

29.15 What Is a Scalar Subquery?

A scalar subquery returns a single value: one row containing one column.

I can use it in places where a single value is expected, such as a comparison or an expression in the SELECT list.

SQL — Scalar Subquery 
SELECT
    student_name,
    fees
FROM course_enrollments
WHERE fees = (
    SELECT MAX(fees)
    FROM course_enrollments
);

MAX() returns one value, so the inner query is suitable for this comparison.

29.16 What Happens if a Scalar Subquery Returns Multiple Rows?

A scalar subquery is expected to return at most one row and one column.

If I use an ordinary comparison operator such as = with a subquery that returns multiple rows, MySQL produces an error.

For example:

SQL — Multiple Rows in a Scalar Comparison 
SELECT
    student_name
FROM course_enrollments
WHERE fees = (
    SELECT fees
    FROM course_enrollments
    WHERE course = 'CSS'
);

If CSS has more than one enrollment, the inner query returns multiple values. The equality comparison cannot use that multi-row result as a scalar value.

I can use IN instead:

SQL — Using IN for Multiple Values 
SELECT
    student_name
FROM course_enrollments
WHERE fees IN (
    SELECT fees
    FROM course_enrollments
    WHERE course = 'CSS'
);

29.17 What Is a Correlated Subquery?

A correlated subquery is an inner query that refers to a column from the outer query.

Unlike a simple independent subquery, it depends on values from the current row being considered by the outer query.

For example, suppose I want to find students whose fees are greater than the average fees of their own course.

SQL — Correlated Subquery 
SELECT
    ce.student_name,
    ce.course,
    ce.fees
FROM course_enrollments AS ce
WHERE ce.fees > (
    SELECT AVG(inner_ce.fees)
    FROM course_enrollments AS inner_ce
    WHERE inner_ce.course = ce.course
);

The inner query uses ce.course from the outer query to calculate the average fee for that particular course.

The outer query then compares each student's fees with that course's average.

Correlated subqueries are useful for row-by-row comparisons, although their performance depends on the query, indexes, and MySQL's execution strategy.

29.18 Nested Subqueries — One Subquery Inside Another

SQL also allows nested subqueries, meaning a subquery can contain another subquery.

For example, I may want to find students enrolled in the course having the highest total fees.

SQL — Nested Subqueries 
SELECT
    student_name,
    course,
    fees
FROM course_enrollments
WHERE course = (
    SELECT course
    FROM course_enrollments
    GROUP BY course
    ORDER BY SUM(fees) DESC
    LIMIT 1
);

The inner query identifies the course with the highest total fees. The outer query then retrieves students enrolled in that course.

29.19 Subquery vs JOIN

While learning subqueries, I also wanted to understand how they differ from JOINs. Both can help retrieve information from related tables, but they express the problem differently.

  • JOIN: Combines columns from related tables into one result set.
  • Subquery: Uses the result of one query inside another query.

For example, I can find students who have an enrollment using JOIN:

SQL — Using JOIN 
SELECT DISTINCT
    s.student_id,
    s.student_name
FROM students AS s
INNER JOIN enrollments AS e
ON s.student_id = e.student_id;

I can express the same requirement using EXISTS:

SQL — Using a Subquery 
SELECT
    s.student_id,
    s.student_name
FROM students AS s
WHERE EXISTS (
    SELECT 1
    FROM enrollments AS e
    WHERE e.student_id = s.student_id
);

Both approaches can be useful. I should choose the one that expresses the requirement clearly and performs well with the actual database structure.

  • A subquery is a query written inside another SQL query.
  • The inner query is also called a nested query.
  • Subqueries are commonly enclosed in parentheses.

30. EXISTS and NOT EXISTS — Checking Whether Records Exist

In the previous chapter, I learned about subqueries and how one SQL query can be written inside another. I also explored operators such as IN, NOT IN, ANY, and ALL.

While working with related tables, I sometimes need to check whether a matching record exists rather than retrieve the actual matching values.

For example, imagine I have two tables: students and enrollments. I may want to find students who have registered for at least one course. I may also want to find students who have not registered for any course.

Instead of joining and displaying matching records, I can use EXISTS and NOT EXISTS to check whether a matching record is present.

30.1 What Is EXISTS in SQL?

EXISTS is a logical operator used with a subquery. It checks whether the subquery returns at least one row.

If the subquery returns one or more rows, EXISTS evaluates to TRUE. If it returns no rows, EXISTS evaluates to FALSE.

The important thing I learned is that EXISTS checks the existence of rows. It does not need the actual values returned by the subquery.

30.2 Basic Syntax of EXISTS

SQL — EXISTS Syntax 
SELECT column_name
FROM table_name
WHERE EXISTS (
    SELECT 1
    FROM another_table
    WHERE condition
);

Here:

  • SELECT: Retrieves columns from the outer table.
  • EXISTS: Checks whether the inner query returns any rows.
  • Inner Query: Searches for matching records.
  • Condition: Defines which records should be considered a match.

30.3 Understanding EXISTS with Two Tables

To understand EXISTS practically, I will create two related tables: students and enrollments.

The students table stores student details, while the enrollments table stores the courses selected by students.

30.4 Finding Students Who Have Enrolled in Courses

Suppose I want to display only those students who have at least one enrollment.

I can use EXISTS to check whether the enrollments table contains a record for each student.

30.5 How Does EXISTS Check Matching Records?

To understand the previous query, I need to look at the condition inside the subquery:

SQL — Matching Condition 
WHERE e.student_id = s.student_id

Here, e.student_id belongs to the enrollments table, while s.student_id belongs to the students table.

SQL checks whether an enrollment exists for the student currently being considered by the outer query.

If a matching record exists, that student is included in the final result.

30.6 Understanding NOT EXISTS

NOT EXISTS works in the opposite way. It checks whether the subquery returns no rows.

  • EXISTS: TRUE when at least one matching row exists.
  • NOT EXISTS: TRUE when no matching row exists.

This makes NOT EXISTS useful when I want to find records that do not have a related record in another table.

30.7 Basic Syntax of NOT EXISTS

SQL — NOT EXISTS Syntax

30.9 What Is a Correlated Subquery?

The EXISTS and NOT EXISTS examples above use a concept called a correlated subquery.

A correlated subquery is an inner query that refers to a column from the outer query.

In our example:

SQL — Correlated Reference 
WHERE e.student_id = s.student_id

The inner query uses s.student_id, which comes from the outer students table.

This connection allows the inner query to check enrollments for the student currently being evaluated.

Similarly, I can use NOT EXISTS to find students who have not enrolled in HTML, even if they may have enrolled in another course.

I can combine multiple conditions inside the subquery using AND and OR.

30.13 Difference Between EXISTS and IN

EXISTS and IN can sometimes solve similar problems, but their logic is different.

  • IN: Checks whether a value matches a value in a list or subquery result.
  • EXISTS: Checks whether the subquery returns at least one row.

For example, using IN:

SQL — Using IN 
SELECT
    student_name
FROM students
WHERE student_id IN (
    SELECT student_id
    FROM enrollments
);

The same existence requirement can be expressed using EXISTS:

SQL — Using EXISTS 
SELECT
    s.student_name
FROM students AS s
WHERE EXISTS (
    SELECT 1
    FROM enrollments AS e
    WHERE e.student_id = s.student_id
);

Both queries can return students with matching enrollment records. EXISTS directly expresses the requirement that a related row must exist.

30.14 Difference Between NOT EXISTS and NOT IN

This is an important distinction because NULL values can affect NOT IN results.

Consider this query:

SQL — NOT IN Example 
SELECT
    student_name
FROM students
WHERE student_id NOT IN (
    SELECT student_id
    FROM enrollments
);

If the inner query returns a NULL value, the NOT IN comparison can evaluate to UNKNOWN for values that otherwise might have matched the condition. This can cause the query to return no rows unexpectedly.

NOT EXISTS checks for the absence of a matching row and is generally a safer way to express this type of requirement.

SQL — Safer Missing-Record Check 
SELECT
    s.student_name
FROM students AS s
WHERE NOT EXISTS (
    SELECT 1
    FROM enrollments AS e
    WHERE e.student_id = s.student_id
);

30.15 Why Do We Write SELECT 1 Inside EXISTS?

In many SQL examples, I noticed that developers write SELECT 1 inside EXISTS instead of selecting an actual column.

SQL — SELECT 1 
WHERE EXISTS (
    SELECT 1
    FROM enrollments
    WHERE student_id = 1
);

The reason is simple: EXISTS only checks whether a row is returned. It does not use the selected column value.

Therefore, SELECT 1 is a clear and conventional way to write an existence check.

SELECT * or SELECT a_column can also be used with EXISTS. Writing SELECT 1 does not automatically make the query faster; the database optimiser handles the execution.

WHERE EXISTS (
    SELECT 1
    FROM students AS s
    WHERE s.student_id = enrollments.student_id
    AND s.status = 'inactive'
);

Before running a DELETE statement, I should always preview the matching records with a SELECT query and ensure that the intended rows are selected.

EXISTS can also be used to update records when a related row exists.

For example, I can mark a student's enrollment as verified when that student exists in the students table.

WHERE EXISTS (

    FROM students AS s

);

This example assumes that the enrollments table contains a status column.

31. UNION and UNION ALL — Combining Results from Multiple SELECT Statements

While learning SQL, I discovered that sometimes data is stored in different tables, but I may need to display information from those tables together in a single result.

Until now, I have learned about JOIN, which combines related information from multiple tables using columns and relationships. But what if I want to combine the results of two or more SELECT statements by placing their rows one after another?

This is where UNION and UNION ALL become useful. They allow me to combine the result sets of multiple SELECT queries into one result set.

31.1 What Is UNION in SQL?

UNION is an SQL set operator used to combine the results of two or more SELECT statements.

It combines the rows returned by each SELECT query and removes duplicate rows from the combined result.

In simple words, UNION brings records together and displays each distinct result row only once.

31.2 Basic Syntax of UNION

SQL — UNION Syntax 
SELECT column_name
FROM table1

UNION

SELECT column_name
FROM table2;

Here, both SELECT statements produce results that are combined into one result set.

31.3 Rules for Using UNION

Before combining SELECT statements, I need to understand some important rules.

  • Every SELECT statement must return the same number of columns.
  • The corresponding columns should have compatible data types.
  • The columns are matched by their position, not by their names.
  • The final column names are generally taken from the first SELECT statement.
  • UNION removes duplicate complete rows from the combined result.
  • UNION can combine results from more than two SELECT statements.

31.4 Understanding UNION with Two Tables

To understand UNION, I will create an example using two tables: current_students and previous_students.

Both tables contain student names, and I want to display a combined list of students without repeating duplicate names.

Current Students Table

2Priya
3Aman

Previous Students Table

student_id student_name
4Simran
5Rahul
6Pooja

Notice that Pooja appears in both tables. If I combine the student names using UNION, the duplicate name will appear only once.

SQL — Combining Student Names Using UNION 
SELECT student_name
FROM current_students

UNION

SELECT student_name
FROM previous_students;

The combined result contains:

student_name
Pooja
Priya
Aman
Simran
Rahul

Pooja appears only once because UNION removes duplicate result rows.

31.5 What Is UNION ALL in SQL?

UNION ALL also combines the results of multiple SELECT statements. However, unlike UNION, it does not remove duplicate rows.

It keeps all rows returned by the individual SELECT statements.

This means that if the same record appears in both result sets, it can appear more than once in the final result.

31.6 Basic Syntax of UNION ALL

SQL — UNION ALL Syntax 
SELECT column_name
FROM table1

UNION ALL

SELECT column_name
FROM table2;

Now I will use the same current_students and previous_students tables.

This time, I want to keep every student name, including repeated names.

SQL — Combining Student Names Using UNION ALL

SELECT student_name
FROM previous_students;

student_name

Priya
Aman
Simran
Rahul

Here, Pooja appears twice because UNION ALL preserves duplicate rows.

31.8 Difference Between UNION and UNION ALL

UNION UNION ALL
Combines multiple SELECT results. Combines multiple SELECT results.
Removes duplicate complete rows. Preserves duplicate complete rows.
May require extra work for duplicate elimination. Does not perform duplicate elimination.
Useful when I need distinct combined results. Useful when I need every returned row.

I learned that UNION ALL can often be more efficient because it does not need to remove duplicates. However, the correct choice depends on what result my application actually needs.

31.9 UNION with Multiple Columns

UNION is not limited to combining a single column. I can combine multiple columns as long as every SELECT statement returns the same number of compatible columns.

For example, I want to combine student names and course names from two tables.

SQL — UNION with Multiple Columns 
SELECT
    student_name,
    course_name
FROM current_enrollments

UNION

SELECT
    student_name,
    course_name
FROM previous_enrollments;

This query combines two-column records. A row is considered a duplicate only when all corresponding selected values match.

For example, Pooja with HTML and Pooja with CSS are different rows because their course_name values are different.

31.10 Column Positions and Compatible Data Types

One important thing I learned is that UNION matches columns according to their positions.

It does not automatically match columns based on their names.

SQL — Column Position Example

    student_name,
    student_id
FROM current_students

UNION

SELECT
    student_name,
    student_id
FROM previous_students;

In this example, the first column is combined with the first column, and the second column is combined with the second column.

If I accidentally change the column order in the second SELECT statement, the resulting values may no longer represent the information I intended.

Therefore, I should keep the column order consistent and use compatible data types.

    student_name,
    student_id

The final result uses the column names from the first SELECT statement. The aliases in later SELECT statements do not rename the final output columns.

31.12 Using ORDER BY with UNION

When I combine multiple SELECT statements, I may also want to arrange the final result in ascending or descending order.

I can use ORDER BY after the final SELECT statement.

SQL — UNION with ORDER BY 
SELECT student_name
FROM current_students

UNION

SELECT student_name
FROM previous_students

ORDER BY student_name ASC;

This sorts the combined result by student_name in ascending order.

The ORDER BY clause at the end applies to the complete UNION result, not just the second SELECT statement.

While learning SQL, I noticed that UNION and JOIN both combine information, but they work in different ways.

JOIN combines columns from related tables, while UNION combines rows from multiple SELECT results.

    s.student_name,
    e.course_name

Example: Combining student names from two different student tables.

SQL — UNION

UNION

SELECT student_name
FROM previous_students;

This difference helped me understand when to use JOIN and when to use UNION.

31.18 Understanding UNION with NULL Values

SQL also allows NULL values in UNION result sets.

For example, if one table contains a missing phone number, I can still combine its records with another compatible result set.

SQL — UNION with NULL

    student_name,
    phone

    student_name,
    NULL
FROM previous_students;

The second SELECT supplies NULL as the phone value because it does not retrieve a phone column.

UNION treats NULL values as equal for duplicate elimination in this context, so rows with matching selected values can be removed.

31.19 Using UNION ALL for Activity Reports

UNION ALL is useful when I want to preserve every record from multiple sources.

For example, imagine I have two tables containing login activity from different periods.

    user_id,

    user_id,
    login_time

31.20 UNION and Parentheses

Sometimes I may need to apply ORDER BY or LIMIT to an individual SELECT query before combining it with another result.

In MySQL, I can use parentheses around individual SELECT statements when I need to control their individual ordering or limits.

SQL — Parenthesized UNION Queries 
(
    SELECT student_name
    FROM current_students

    LIMIT 2
)

    SELECT student_name
    FROM previous_students
    ORDER BY student_name ASC
    LIMIT 2

Here, each SELECT has its own LIMIT. If I want to sort the complete combined result as well, I can add a final ORDER BY after the UNION expression.

32.16 Understanding Prepared Statements

One of the most important things I learned while connecting PHP with MySQL was the use of prepared statements.

32.17 What Is SQL Injection?

SQL injection is a security vulnerability that can occur when untrusted input is inserted directly into an SQL query.

For example, this is an unsafe approach:

PHP — Unsafe Query Example 
<?php

$name = $_POST['name'];

$sql = "SELECT * FROM users
        WHERE username = '$name'";

?>

The visitor's input becomes part of the SQL statement itself. Unexpected input could change the meaning of the query.

This is why I should use prepared statements instead.

32.18 Using Prepared Statements with MySQLi

MySQLi provides prepare(), bind_param(), and execute() to work with prepared statements.

PHP — Prepared SELECT Statement 
<?php

require_once __DIR__ . '/db_connect.php';

$username = "Pooja";

$stmt = $conn->prepare(
    "SELECT id, username
     FROM users
     WHERE username = ?"
);

$stmt->bind_param("s", $username);

$stmt->execute();

$result = $stmt->get_result();

while ($row = $result->fetch_assoc()) {
    echo $row['username'];
}

$stmt->close();

?>

Let me understand the important parts:

  • prepare(): Prepares the SQL statement containing placeholders.
  • ? Represents a parameter placeholder.
  • bind_param(): Binds PHP variables to the placeholders.
  • "s": Indicates that the supplied parameter is a string.
  • execute(): Executes the prepared statement.
  • get_result(): Retrieves a result set when supported by the installed MySQLi driver.
  • close(): Releases the prepared statement resources.

MySQLi bind_param() type characters include:

  • i: Integer.
  • d: Floating-point number.
  • s: String.
  • b: Binary data.

The number and order of type characters must match the bound parameters.

    ]);

// Step 1: Read incoming form values

$name = trim($_POST['name'] ?? '');
$email = trim($_POST['email'] ?? '');
$message = trim($_POST['message'] ?? '');

    $name === '' ||

    $message === ''

    echo json_encode([
        "success" => false,
        "message" => "Please fill all fields."
    ]);

    echo json_encode([
        "success" => false,
        "message" => "Invalid email address."
    ]);

}

$stmt = $conn->prepare(
    "INSERT INTO contact_messages
     (name, email, message)
     VALUES (?, ?, ?)"

    "sss",
    $name,
    $email,
    $message

    // Step 7: Send success response

    echo json_encode([
        "success" => true,
        "message" => "Your message has been saved!"

        "success" => false,
        "message" => "Something went wrong."
    ]);

// Step 8: Release statement resources
